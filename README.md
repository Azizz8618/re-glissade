# «Глиссада-6» — реконструкция игры и тренажёра для БЭСМ-6

**БЭСМ-6 · ОС ДИСПАК («Дубна») · ФОРТРАН ИПМ (ФОРЭКС) · Паскаль · PERSO зона 2700(8)**

Реконструкция игры-тренажёра захода на посадку «Глиссада» в вычислительных
технологиях 1975–1980 гг. и постепенное превращение её в учебный тренажёр
по организационным принципам системы К-71 морского тренажёра «Диана-БАРС».
Оригинальные исходники игры публично не обнаружены; пакет написан заново
как добросовестная реконструкция эпохи.

## Что моделируется

- посадка по глиссаде **3°** с вводом с **15 км** (высота 786 м);
- пять типов самолётов: **МиГ-15, Ил-28, Ту-104, Ан-24, Ан-2**;
- **шесть степеней свободы**, ориентация кватернионом (13-компонентный
  вектор состояния), интегрирование Рунге–Кутта 4-го порядка, шаг **0,1 с**;
- турбулентность — фильтр Орнштейна–Уленбека по трём каналам;
- **контроль точности** по Кутта–Мерсону (`SRC/GLKM.FTN`) вместо недоступной
  подпрограммы СБ `АД01`;
- двигатели ТРД и ТВД (упрощённые дроссельные характеристики);
- два режима: **АВТОМАТ** (автопилот захода) и **ПРОГРАММА** (пилотирование
  задано колодой карт);
- **интерактивный диалог на Паскале** с печатью поля варианта C;
- вывод кадра на **АЦПУ** (профиль, план сверху, две шкалы) и оценка посадки.

### Возможности тренажёра (этапы 1–9)

| Команда | Действие |
|---|---|
| `STA` / `STE` / `STO` | пуск / шаг / остановка расчёта |
| `PAR` / `PRN` / `EXIT` | параметры / печать кадра / выход |
| `PIL` / `INS` | режим пилота / инструктора |
| `SEL N` | выбрать упражнение T1…T5 |
| ручной пилот T2 | скрипт подаёт `EV/TH` по шагам; посадка в грозу |
| `FRZ` / `UNF` | заморозка / снятие заморозки |
| `INJ N` | ввести отказ (1 – потеря тяги, 2–4 – заклинивание рулей, 5 – сдвиг ветра) |
| `EV±` / `AI±` / `RU±` / `TH±` | ручное управление рулями и тягой |
| `AUTO` | вернуть управление автопилоту |
| `REC` / `RPL` / `RST` | запись траектории / печать телеметрии / сброс записи |
| `SCR` | дебрифинг: таблица ошибок и итоговая оценка |
| `HLP` | справка по командам |

Команды вводятся заглавными латинскими буквами, до шести литер. Латинская
`Y` в командах недопустима — в кодировке видеотона она читается как
кириллическая `У` (поэтому команда воспроизведения называется `RPL`).

## Принцип аутентичности

- фиксированный формат колод: колонки 1–72, продолжения в колонке 6;
- нет блочных `IF`, нет типа `CHARACTER`, нет структур;
- русский текст на АЦПУ — только Холлеритом (ГОСТ 10859);
- управление — вычисленные `GOTO`, арифметические `IF`;
- случайные числа — генератор Лемера;
- приглашение `WHAT=` подавляется ответом `L0`, а `PASTEL[3]:=[48]` задаёт
  поле варианта C;
- все корректируемые параметры новых модулей вынесены в отдельные блоки
  (`/SCPAR/`, `/RECPAR/`, `/FAULT/`) — см. `docs/corrections.md`.

## Запуск

### Классическая колода

1. Собрать симулятор БЭСМ-6 и получить образы ДИСПАК — `docs/ETAP0.TXT`.
2. Подать `JOB/GLISSADA.B6` на `dispak` (обвязка `TOOLS/run_save_pty.py`
   отвечает на приглашение `WHAT=`).
3. Другие варианты — заменить карты данных из `DATA/`.

### Интерактивный диалог (рекомендуется)

```bash
cd ~/Yandex.Disk/re-glissade
sh TOOLS/install-2348.sh 1
python3 TOOLS/play.py
python3 TOOLS/calib/scenarios.py verify   # исторические сценарии
python3 TOOLS/exercises.py verify         # упражнения
python3 TOOLS/exercises.py score          # оценка задания
python3 TOOLS/replay.py verify            # побайтовый повтор
```

Ядро и оболочка записываются в `~/.besm6/2348`, зона `2700(8)`; перед
записью зона очищается через `besmtool zero`, создаётся резервная копия.

## Библиотека СБ (том 2048)

- `CALL ATM(HG,TK,RHO)` — стандартная атмосфера, катал. **АЗ01**;
- `CALL NR(RN)` — нормальная случайная величина, катал. **АВ07**;
- **АД01** (Кутта–Мерсон) заменена на `SRC/GLKM.FTN`.

Недоступные обращения собраны в `SRC/GLNUM.FTN`, запасной адаптер —
`SRC/GLNUMR.FTN`.

## К-71 и СМ-2

Тренажёр развивается по организационным принципам системы **К-71** —
вычислительного комплекса морского тренажёра «Диана-БАРС» для АПЛ проекта 971
(НИТИ им. А. П. Александрова, 1983–1988). К-71 не является авиационным
тренажёром; заимствуются только уровни ТОР/СОИ/ПВС/СПД/ЦВС, пульт
руководителя, упражнения, аварийные вводные, масштабы времени и объективная
оценка. Первичный источник — `Описание.pdf` (К71.05.01.00 ТО, 1983).

Изучена периферийная вычислительная система: **три СМ-2** исполняют задачи
ПВС, а **«Электроника-60»** — шлюз уровня СПД (ДКС/КАДОПАМ/КРК). Оба
эмулятора есть в `../simh`: `hp2100` (порт на СМ-2) и `pdp11` с устройством
`pdp11_dks.c`. Подробности:

- `docs/PLAN-TRENAZHER-K71.md` — план и GAP по К-71;
- `docs/analysis/pvs-materialy.md` — ПВС, СМ ЭВМ, «Электроника-60»;
- `docs/analysis/sm2-vs-hp2000.md` — сравнение систем команд;
- `docs/analysis/sm2-port-plan.md` — план порта hp2100 → СМ-2;
- `docs/analysis/sm2-tests-osint.md` — тесты связи с СМ-2;
- `docs/analysis/glissada-new-materials.md` — новые сканы (`ТЕСТ_СВЯЗЬ_СМ-2.pdf`,
  `К71.07.00.00 ТО`).

Задачи ПВС исполняются на эмулируемой СМ-2 (`TOOLS/sm2_tasks/`: `PS1…PS4`,
`TIME`, `RCV`, `SND`, `RCD`, `WCD`); ассемблер — `TOOLS/sm2asm.py`, прогон —
`TOOLS/ps2_run.py`, тактирование — `TOOLS/timeline.py`, доставка команд
пилота — `TOOLS/pilot_queue.py`. Клиент моста
`TOOLS/sm2_dks_bridge.py` проверен против живого `pdp11_dks.c` (PING/READ/WRITE).
Кодировка команд СМ-2 объявлена в `../simh/HP2100/sm2_params.h` и не сверена
с подлинным железом — задачи гарантированно работают только на нашем эмуляторе.
Подробности — `docs/PLAN-PERIFERIYA.md` и `docs/analysis/ps2-sm2-tasks.md`,
`sm2-dks-bridge.md`, `dks-bridge-runbook.md`.

### Известные ограничения и GAP

- подпрограммы стандартной библиотеки не подключены — работают запасные
  адаптеры;
- при `SIGW>0` автопилот МиГ-15 неустойчив; упражнение T2 решено
  ручным пилотом (`TOOLS/exercises.py`), сам автопилот остаётся GAP;
- контроль Кутта–Мерсона оценивает погрешность, но не изменяет шаг; подлинная `АД01` с диска 2248 делает автоматический выбор шага — подтверждённый GAP (см. `docs/analysis/kutta-merson.md`);
- в порту СМ-2 точные битовые раскладки кодов отсутствуют в источнике —
  кодировка объявлена в `sm2_params.h`, бинарная совместимость с подлинными
  программами не гарантирована;
- этап 10 (масштабы времени) выполнен: `TOOLS/timeline.py`; очередь событий
  пилота и доставка команд на границах шага — `TOOLS/pilot_queue.py` (Q6).

Чистый прогон — `RUNS/run-2026-11-17-clean/`; подробности —
