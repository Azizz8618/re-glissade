## 1. Аэродинамика и ЛТХ самолётов

В `GLINITD.FTN` задаётся **28 параметров на тип**. После сбора шести книг
документально подтверждены не все из них. Обозначения: `[Д]` — подтверждено
документом, `[О]` — оценка, `[Д!]` — документ есть, но значение в коде другое.

### 1.1 Ядро неподтверждённых данных — 7 параметров × 5 типов = 35 ячеек

| Группа | Параметры | Почему важно | Можно ли получить |
|---|---|---|---|
| Моменты инерции | `JX, JY, JZ` | знаменатели в `XD(8..10)=(AM+гироскопический член)/J` — частота и перерегулирование тангажа/крена, реакция на турбулентность | **Нет** в открытых источниках; только архивы ЦАГИ/ЛИИ или расчёт по массе и геометрии |
| Демпфирующие | `CLP, CNR, CMQ` | единственное аэродинамическое демпфирование в модели; `CMQ` критичен на выравнивании | **Нет**; книга Согалова 1953 их не содержит; отчёты по штопору/устойчивости закрыты |
| Геометрия касания | `HCR` | детектор касания в `GLMAIN:86` и порог выравнивания в `GLAUTO` | прямых чисел нет; осознанная игровая подмена |

### 1.2 Неподтверждённые по типам (кроме ядра)

| Тип | Число | Что именно |
|---|---|---|
| МиГ-15 | 13 | `CL0, CD0, CNDR, THMAX, VTHR` + `CC` + ядро. Девять производных подтверждены книгой ЦАГИ 1953, но **код не обновлён** |
| Ил-28 | 15–16 | `CL0, CLA, CLMX, CD0, CMA, CM0, CMDE, CLB, CLDA, CNB, CNDR, CYB, VTHR` + ядро. Скорость захода **не найдена** |
| Ту-104 | 22 | почти всё, включая `CC=5.4`, `AK=0.115`, `THMAX=168000`, `CLMX=1.35` + ядро |
| Ан-24 | 20 | `CC, CL0, CLA, CD0, CM*, CLB..CYB, THMAX` + ядро; `CLMX=1.60` подтверждено только для чистого крыла |
| Ан-2 | 17 | все моментные/боковые + ядро; `CL0/CD0/CLMX/CLA` подтверждены полярами Шифрина |

### 1.3 Противоречия документ ↔ код — главный резерв точности

| Тип | Параметр | В коде | По документу | Решение |
|---|---|---|---|---|
| Ил-28 | `CLMX`/`VTHR` | 1.95 / 55 м/с | ~1,57 / ~69 м/с | менять только парой + перекалибровка ветки 200 |
| Ан-24 | `CLMX` | 1.60 | 1,615 (чистое) / 2,57 (δз=38°) | решить, какую конфигурацию моделирует |
| Ту-104 | угол глиссады | 3° (786 м) | 2°40' (699 м), 3°30' при препятствиях | захардкожен в 8 местах |
| МиГ-15 | `GM` | 5000 | 3915 посадочная | завышена на 28% |
| Ил-28 | `GM` | 21000 | 14750 посадочная | завышена в 1,4 раза |
| Ту-104 | `GM` | 62000 | 53000/58000 базового | число от модификаций А/Б/В/Д |
| все | `CC` | 2.0 / 3.1 / 2.9 | 2.12 / 2.955 / 2.813 | влияет на `QH` и плечо момента |
| все | высота выравнивания | `HCR+32/61/20/170/3` м | 6–15 м по РЛЭ | осознанная игровая подмена |

**Вывод:** гнаться за закрытыми 30 параметрами нецелесообразно (автопилот частично компенсирует их неточность). Главный резерв — исправление **документированных** противоречий с обязательной перекалибровкой `GLAUTO`.

## 2. Диспак и PERSO-линковка

### 2.1 Что не эмулируется

| Механизм | Чего не хватает | Причина |
|---|---|---|
| Линковка PERSO `C=0o6700` | обход sym-таблиц, подмена каталожного слова переходом, запись точки входа |Диспак не загрузчик — тела размещает эмулируемый Монитор-80; обработки `0o6700` в коде нет |
| Контекст вызова зоны `71000` | нет корректного возврата (`71011` — константа), аргументов, acc; `М4=03077` уводит в данные | FOREX сгенерировал call-site в `SBATM` (`10144`), но переход идёт мимо него |
| Полная релокация DMS | теги `4`/`7`, разделы cmd/sym/long | в этой конфигурации не требуется — тела уже по адресам |
| Супервизор Э62/Э63 | только минимальный trap-контекст; мини-супервизор тома 2099 обслуживает Э64/Э66/Э62 41/Э50 104 и один процесс |Диспак — пакетный эмулятор уровня пользователя, не машина |
| Произвольные физические адреса | `physaddr()` — ~20 хардкоженных адресов, остальное `E_UNIMP` | нет семантики физических ячеек |
| Э70 / каналы 45,46,54 | хостовые хаки через env вместо состояния канала |Dispatch подменяет device-семантику файловым I/O |
| LTAPES / LIBRARY | хост не разбирает `*LIBRARY` — это делает код Монитора-80; список в `core[0o73]` пересоздаётся | конфигурация живёт в эмулируемой памяти |
| Динамический загрузчик «Дубна» | сборка программы, настройка адресов, временная библиотека | не реализован; ссылка [35] в книге «Фортран-Дубна» локально недоступна |

### 2.2 Что есть / что частично

**Есть:** sym-строка `(0o4000+X)<<24|C<<12|D`, запись каталога PERSO (но без адреса тела), переходные слова `10144`/`7765`, карта символов `loadmap-*`, исходники мини-супервизора, формат карты/паспорта задачи.

**Частично:** формат тела DMS есть, полный алгоритм релокации — нет; первая точка расхождения в зоне `71000` найдена, полная модель call-site — нет.

**Нет:** готовой карты LTAPES (пересоздаётся при старте, каталог не хранит номер тома), полной таблицы `physaddr`, валидированного simh-эталона.

### 2.3 Почему нельзя проверить точность

simh BESM6 — machine-level эталон с подлинной ОС ДИСПАК, но проект его не использовал (`ETAP0.TXT:36-38`: «simh не потребовался»). Попытка эталона была (`UVU/glissada_etalon.ini`), колода принимается (`В075-1 419999000000`), но в логе `ОШИБ` и `3,T001`, расшифровки нет, `ACPU/output.txt` не содержит «ОЦЕНКА ПОСАДКИ». Причины: колода адаптирована подДиспак (латиница, `*forex`, нет `ЛЕН 41(2048)`), разная среда/тома, неопределена семантика `ОШИБ`.

### 2.4 Три главных data gap

1. **Полный алгоритм загрузчика «Дубна» + соглашение вызова** — без него невозможно восстановить `71000 → ATM → возврат`; искать: реверс зоны по дампам/трассам, `loader.md`, `siprod_lib.py`, исходники монитора, ссылка [35], fork `glissada-perso-link`.
2. **Карта системных таблиц** (LTAPES + physaddr + каталоги СБ) — LTAPES пересоздаётся, каталог не хранит номер тома; искать: дампы ядра (`core[0o73]`, ОЗУ `0104000…`), `loadlibr.asm`, образ тома 2048, Мазный, Тюрин.
3. **Валидированный simh-эталон + модель супервизорного контекста/Э70** — расшифровать `ОШИБ`/`3,T001`, привести колоду к формату simh, снять печать до «ОЦЕНКА ПОСАДКИ»; `Mini-Supervisor.txt`, `ekdisp.b6`, `rukava.be`.

**Вывод:** PERSO закрыто не потому, чтоДиспак «плохо эмулирует Э62», а потому что отсутствует целый слой — загрузчик с соглашением вызова, системные таблицы и machine-level эталон.

## 3. Среда, атмосфера, турбулентность, валидация

### 3.1 Жёстко заданные константы без источника

| Константа | Значение / место | Почему выбрана | Что нужно |
|---|---|---|---|
| Угол глиссады | 3° (`0.05241`) в 8 местах | стандарт ILS, игровая константа | ICAO Doc 8168; РЛЭ Ту-104 даёт 2°40' |
| Вход в глиссаду | 15 км → 786 м | 15000×tg3° | схема захода ВПП; при 2°40' было бы ~699 м |
| Шаг РК-4 | 0.1 с | компромисс точность/скорость | оценка локальной погрешности Кутта–Мерсона реализована в `GLKM.FTN` |
| Порог срыва | `ALFS=0.30 рад` (17.2°) | типовой α_max | поляра `C_y(α)`; для посадочной конфигурации иной |
| g | 9.81 в `GLPROIZ` против 9.80665 в атмосфере | округление | единая константа по ГОСТ 4401/ISA |
| Холостой ТРД | `0.06+0.94·DTZ` | 6% тяги | дроссельная характеристика двигателя |
| Спад тяги | `1−0.0006·VA` | линейная аппроксимация | паспорт `T(V)`; при V>1667 м/с формула физически неверна |
| КПД винта ТВД | `1.6·PMAX/V` | **η=1.6 > 1 физически невозможно** | реально 0,77–0,9; но при V=57 результат «спрятан» под `THMAX`, так что правка почти ничего не изменит |
| Автопилот | `GE=0.50/0.08`, смещения −18/−20 м, высоты `HCR+32/61/20/170/3`, демпферы | всё подобрано в Фазе 3 | только `phase3-rezultaty.md`; реальные законы САУ неизвестны |
| Пороги оценки | 1.5 / 2.5 / 4.0 м/с | игровая шкала | нет нормативного документа;_order K=1..4 произволен |

### 3.2 Атмосфера

МСА в `GLNUMR` (`T=288.15−0.0065H`, `ρ=1.225(T/288.15)^4.2559`, изотерма 11 км) **внутренне согласована** и совпадает с ГОСТ 4401-81 / ICAO до 20 км; для высот 0–786 м адекватна. Не хватает:
1. рабочего кода/таблиц библиотечной ATM (СБ АЗ01) — сигнатура по Мазному взята, но формулы не исполнялись;
2. реальных метеоданных для воспроизведения конкретного захода (ISA-deviation, QNH, ветер по высоте) — METAR/радиозонд;
3. устранения дубля `g` (9.81 против 9.80665).

### 3.3 Турбулентность

Модель Орнштейна–Уленбека: `DW/DT=−W/τ+σ√(2/τ)ξ`, `τ=1.0 с` жёстко, `σ=1.5` из карты, три независимых канала. Не хватает:
- происхождения `τ=1 с` (физически τ≈L/V ≈1,3–8 с);
- масштабов `L_u,L_v,L_w(h)`, зависимости `σ_w(h)` от ветра, спектра (Dryden/von Kármán, MIL-HDBK-1797);
- советских данных по спектрам (Кафёров/ЦАГИ — в открытом доступе не найдены);
- корреляции каналов и градиентов порывов (модель применяет один W ко всему самолёту);
- подтверждения, что СБ NR совпадает с ЦПТ-приближением по моментам.
Признак несогласованности: при σ=1,5 м/с касание за 4 м до порога и авария.

### 3.4 Валидация Диспак ↔ реальный БЭСМ-6

Главные барьеры:
- ошибка «ИСПОРЧЕН РЕКОРД POINT 00012/00044» вДиспак устранена затравкой `seed-k12.bin` (`ETAP1.TXT` п. 18.10), но **штатный ввод напрямую из колоды** по-прежнему не работает — рабочий путь использует искусственную затравку;
- формат листа-конверта МОНА-80 и кодировка (ГОСТ 10859 6 бит vs ISO 8 бит, 0x1d/0o35, EOR=0o12) не описаны эталоном — PRINTFILE содержит `\x07` (штатный carriage return АЦПУ, не ошибка) и нестандартный порядок кадров; ошибки 205/232/224 устранены исправлением счётчиков Холлерита (`ETAP1.TXT` п. 19.4);
- нет архивной печати/дампа с реальной машины; исторический `g1r-native4` не воспроизведён побайтово;
- в чистом прогоне `IFLIB=1` не действует (подключён `GLNUMR`) — библиотечный путь атмосферы/РН не проверен;
- нет полной поразрядной сверки экстракодов Э50–Э57 и формата числа.

Для сравнения нужны: битовые образы дисков с контрольными суммами (фиксация `86c7fa7`), колоды, seed `03e9996…`, эталонная печать и core/drum dump на касании (адрес 437).

### 3.5 TOP-5 данных, без которых точная эмуляция недостижима

| № | Чего не хватает | Где взять |
|---|---|---|
| 1 | рабочий код/таблицы ATM+NR (СБ АЗ01/АВ07) | образы 2048/2248/2348, Мазный с.128–139, ГОСТ 4401-81 |

| 3 | нормативная база геометрии и оценки (3°/2°40', 15 км, пороги 1.5/2.5/4.0) | РЛЭ, ICAO Doc 8168, НЛГС/AP-25 |
| 4 | аутентичный конверт ввода и кодировка вывода | дамп стека очередей МОНЫ, ГОСТ 10859, mk_seed_k12.py |

## 4. Итог: TOP пробелов для точной эмуляции

| № | Пробел | Почему критично | Можно ли закрыть |
|---|---|---|---|
| 1 | Демпфирующие (`CLP,CNR,CMQ`) и моменты инерции (`JX,JY,JZ`) — 30 чисел на 5 типов | единственное аэродинамическое демпфирование; задаёт устойчивость тангажа на выравнивании | **Практически нет** — закрытые отчёты ЦАГИ/ЛИИ; только расчётная оценка |
| 2 | Параметры реальной турбулентности: τ, σ, корреляции каналов, спектр | TAU=1 с и σ из карты произвольны; при 1,5 м/с касание до порога | частично — MIL-HDBK-1797, Кафёров/ЦАГИ, метеопрофили |

| 4 | Противоречия документ ↔ код: `GM` трёх типов, угол 3°/2°40', пары `CLMX/VTHR`, `CC` | это **документированные** величины с большим влиянием на результат | **Да** — исправление с перекалибровкой `GLAUTO` |
| 5 | Побайтовый эталон с реальной машины | архивной печати/дампа БЭСМ-6 нет; simh-прогон даёт `ОШИБ`, расшифровки нет | частично — дампы/трассы Диспак и simh, но валидированного golden-результата нет |

**Уточнение по п. 5 (исправление предыдущей формулировки).** Ошибка «ИСПОРЧЕН РЕКОРД» вДиспак **уже устранена** — журнал `ETAP1.TXT`, п. 18.10: затравка `seed-k12.bin` (`TOOLS/mk_seed_k12.py`) прошла весь конверт, `POINT 00012` больше не печатается, `ERRIOM` и 201 отсутствуют. Ошибки печати 205/232/224 тоже устранены (п. 19.4 — исправлены три счётчика Холлерита в `SRC/GLOUT.FTN`), чистый прогон — `RUNS/run-2026-11-17-clean/`. Символ `\x07` в `printfile.txt` — **не мусор, а управляющий код carriage return АЦПУ** (перевод каретки), штатный для печати. «Перестановка кадров» также объясняется порядком вывода записей листа, а не ошибкой. Не закрыта только **побайтовая сверка с реальной машиной**: исторический `g1r-native4` не воспроизведён, а simh-эталон зафиксирован с `ОШИБ` без расшифровки.

**Главный вывод:** физическая часть модели (РК-4, кватернион, МСА до 786 м) реализована корректно. Точность ограничена не ошибками кода, а **отсутствием подтверждённых источников для калибровок** и нерабочим путём библиотеки/ввода. Приоритет по влиянию: №4 (быстро и по документам) > №2/№3 > №1 (closed) > №5.

Стратегия: зафиксировать оценочные коэффициенты как «игровую калибровку» и направить усилия на уточнение документированных противоречий с обязательным прогоном phase3-тестов.
