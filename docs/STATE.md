## 4. ПОРЯДОК СБОРКИ СИМУЛЯТОРА

Проверено на стенде с доступной системой автоматической сборки.

1. Взять фиксацию симулятора, соответствующую базе проекта: **86c7fa7**
   (создана в ту же секунду, что и d3ac7f5). Рабочее дерево:
   `/home/azizz/Yandex.Disk/dispak`.
2. Создать отдельное рабочее дерево без беспокойства основного:
   ```
   git -C /home/azizz/Yandex.Disk/dispak worktree add --detach <каталог> 86c7fa7
   ```
3. Настроить и собрать. Флаги отключения строгой проверки предупреждений
   необходимы: в заплатках есть неиспользуемые переменные.
   ```
   cmake -S <каталог> -B <каталог>/build -DCMAKE_BUILD_TYPE=Release \
         -DCMAKE_C_FLAGS="-Wno-error=unused-variable -Wno-error=unused-but-set-variable"
   cmake --build <каталог>/build -j4
   ```
4. Готовый программный файл: `<каталог>/build/dispak/dispak`.
   Там же создаются образы дисков 2048, 2053, 2099, 2248.

Для раннего варианта **4b0290a** (прогон времени пункта 18.18) порядок тот же.

## 6. БЛИЖАЙШИЙ ШАГ

Фаза 1 завершена. Адрес из пункта 18.32 уточнён: активная ветка находится
по адресам 4414–4423 восьмеричном. Причина ошибки установлена: проверка
сравнивает очередной символ с кодом пробела 040 из ячейки 4632 и находит
вместо пробелов текст начала колоды `*name`. Записка
`docs/analysis/p18.32-201.md` обновлена.

Фаза 2 завершена. Найдена и исправлена причина ошибок печати: в трёх
описаниях формата не совпадали счётчики Холлерита. После исправления
все ошибки ввода-вывода исчезли, печать содержит корректные строки.

Фаза 3 выполнена в основной части. Подобраны коэффициенты автопилота
по типам самолётов: основной тип получает «отлично», остальные — не ниже
«удовлетворительно». Режим ПРОГРАММА тоже работает. Результаты —
`docs/analysis/phase3-rezultaty.md`.

Касание до порога устранено: все четыре типа садятся за порогом без
признака аварии. Турбулентность стабилизирована снижением усиления
автопилота; детерминизм по исходному числу подтверждён. Остался
пограничный случай: в турбулентность касание на 4 м до порога.

Библиотека с 2248 (ATM/NR) перенесена в зону 3000(8) тома 2348;
другие зоны образа не затронуты. Подключение через `*personal
library:413000` делает ATM/NR видимыми, но задача падает.

**Итоговый вердикт по библиотеке (17 ноября 2026 года).** Направление
LIBRARY/PERSO закрыто как тупиковое в текущей конфигурацииDispак.
Пересмотр диагноза по книге Тюрина показал: обработка Э62 вDispак
корректна, `E_UNIMP` на `011225(8)` — правильная реакция, а «блок-запрос»
из утраченного патча `148ed81` книгой не подтверждается. «Команда»
`Э62 74400(М10)` — не вызов системы, а слово записи каталога PERSO,
дизассемблированное как команда. Настоящий барьер — отсутствие вDispак
линковки внешних символов: подмены каталожного слова переходом к телу
модуля (`C = 0o6700`). Все способы подключения (`*LIBRARY:43`, подмена
LIBRARY:1, `*call librefer`) меняют только поиск имени и не убирают падение.

Библиотека в зоне 3000 тома 2348 остаётся в образе как **артефакт**, а не
как доказательство рабочих вызовов ATM/NR. Поддерживаемая конфигурация —
`SRC/GLNUMR.FTN` с атмосферой и датчиком случайных чисел внутри задачи;
чистый прогон — `RUNS/run-2026-11-17-clean/`. Подробности —
`docs/analysis/p18-PERSO-e62-tekhnicheskoe-opisanie.md` и
`docs/PLAN-BIBLIOTEKA.md`.

**Экспериментальная линковка (17 ноября, продолжение).** В отдельной ветке
форкаDispак (`glissada-perso-link`, коммит `0919e83`) реализован хук по
требованию: при трапе на каталожной заглушкеDispак подменяет её готовым
переходным словом из кода `SBATM`/`SBRND`. Практически подтверждено: тело
ATM начинает исполняться, прежний трап Э62 устранён. Полный проход игры
пока не достигнут — после возврата из библиотеки отказывает `physaddr()`
внутри реализованного Э63 (неподдерживаемый физический адрес `54154(8)`).
Это исследовательский стенд, не замена `GLNUMR`.
Подробности — `docs/analysis/p19-PERSO-link-eksperiment.md`.

**Итог этапа 4 (декомпозиция `docs/PLAN-LINKER.md`).** Три субагента
исследовали зону `71000`, формат загрузчика «Дубна» и путь ATM. Установлено:
подменяемое слово корректно, но зона `71000` — не полноценный call-site
(возврат идёт на `71011`, где данные; стек и acc не несут аргументы ATM);
обход трапы Э62 ломает возврат, на 8-м вызове уходящий в область данных.
Полная релокация здесь не нужна, правка `e62()` недопустима, одной подмены
недостаточно. Направление PERSO остаётся закрытым; рабочая конфигурация —
`GLNUMR`. Проект — `docs/analysis/p20-proekt-linker.md`.
