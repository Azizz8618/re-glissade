# ПЛАН ПЕРИФЕРИЙНЫХ ПОДСИСТЕМ ТРЕНАЖЁРА «ГЛИССАДА-6»

Дата: 18 ноября 2026 года. Составлен по разбору `/home/azizz/Yandex.Disk/re-mrv`
(реконструкция СПО К-71 по `СПО_тексты.pdf`, 335 стр., МАДЛЕН 1.10.72).

## 1. Цель и принцип

Перенести в «Глиссаду» **организационные роли** периферийных подсистем К-71:
приём, выдачу, буферизацию, преобразование форматов, прерывания,
тактирование и диагностику. Не копировать МАДЛЕН-код буквально — он
рассчитан на БЭСМ-6/ДИСПАК и Э-60. В «Глиссаде» те же роли выполняют
Pascal-диалог (`GLDIAL`), Fortran-ядро в PERSO зоне 2700 и хост-процессы.

Источник ролей (пути в `re-mrv`): DOG `src/dog/dog2_compilable.txt`,
MRV `src/mrv/mrv_core.txt`, REA `src/rea/rea_src.txt`, WRI
`src/wri/wri_src.txt`, RCD `src/rcd/`, WCD `src/wcd/`, M7B `src/m7b/`,
PS `src/ps/`, DEB `src/deb/`. Полная сводка — `docs/K71_MRV_SUBSYSTEMS.md`
в `re-mrv`.

## 2. Соответствие подсистем

| Роль в К-71 | Модуль | Аналог в «Глиссаде» | Что сделать |
|---|---|---|---|
| Главная задача, маска событий, запуск ПС | DOG | `GLDIAL` + новый `CMDLOOP` | диспетчер команд и событий, приоритеты, режимы PIL/INS |
| Монитор процессов, «окно», тексты аварий | MRV/PROMON | `GLDIAL` + `TOOLS/*.py` | единый семафор доступа к пульту, таблица сообщений |
| Приём команд, проверка КС, рассылка | REA | `GLRECV` (Fortran) приём пакетов от хоста, контроль, распределение |
| Выдача пакетов на Э-60 и 3 СМ-2 | WRI | `GLSEND` (Fortran) | кольцевой буфер, пакеты, признак конца обмена |
| Приёмная перекодировка | RCD | `GLRCD` | 16/48-разрядные коды → числа БЭСМ-6 |
| Выдающая перекодировка | WCD | `GLWCD` | X(13)/U(4)/T и оценки → пакеты, шкалы |
| Мост форматов M7000 ↔ БЭСМ | M7B | `GLXCOD` | real/int ↔ 16/48 бит ↔ JSON хоста |
| Модели подсистем, время от Э-60 | PS | `GLTIME` | масштабы времени, `PERIOD`, счётчики шагов |
| Отладчик, печать, диагностика | DEB | `GLDEB` | русская диагностика, таблица ошибок, дебрифинг |

Существующие модули `GLRECF`, `GLSCORE`, `GLFAULT` уже закрывают часть
ролей (запись, оценку, отказы) и должны быть **встроены** в новые подсистемы,
а не дублированы.

## 3. Контракты данных (из `re-mrv`)

### 3.1 Дескриптор блока (7 полей)

Из `src/wcd/wcd_src.txt:17-20`, `src/sm2_test/sm2_wint.txt:41-50`:

```
*0 A BLOCK   — адрес начала блока
*1 NUM PS    — номер подсистемы
*2 A PROG    — адрес программы-источника
*3 A TABL    — адрес таблицы
*4 LENG      — длина блока в словах
*5 C NUMB    — номер блока
*6 PERIOD    — интервал шагов (есть не во всех вариантах)
```

В «Глиссаде» это record на Pascal / COMMON на Fortran с полями
`IBLK, IPS, IPROG, ITABL, ILEN, INUM, IPER`. Описатель передаётся через
`STI,9` / `ATI,10` в МАДЛЕН-оригинале; у нас — как параметр подпрограммы.

### 3.2 Формат таблицы выдачи

Из `src/wcd/wcd_real.txt:9-28`, `docs/sm2_test/README.md`:

```
F,ZKK,<имя переменной>   F=00 — одно число; F≠00 — массив до 16 слов
KK = 1:37(8)             интервал шагов
:Z00,                    признак конца таблицы
,Z00,
```

В «Глиссаде»: таблица описаний telemetry — `TOOLS/events/*.json` с полями
`name`, `kind` (int/real/bits/array), `source` (имя переменной ядра),
`period`, `count`. Заменяет МАДЛЕН-таблицу без потери семантики.

### 3.3 Пакет и кольцевой буфер

Из `src/dog/dog2_compilable.txt:820-840`, `src/wri/wri_src.txt:498-519`:

- четыре последовательных пакета: Э-60 + три СМ-2, связанных ссылкой
  `NEXT PCT` (ячейка `-7В`);
- поля пакета: `NNM=6` (номер машины), `N PACK=11`, `BEG COM=12`;
- блок команд: `-0` код команды (`=0` — конец), `-1` число параметров,
  `-N+2` контрольная сумма, `-N+3` код следующей команды;
- слово кольцевого буфера: разряды 1–15 — адрес следующего слова,
  16–31 — код сообщения;
- чтение двухфазное: сначала сумма, затем исполнение (`dog2:812-819`);
- `*50,IN E50` — признак конца обмена.

В «Глиссаде»: JSON-пакет с полями `src`, `seq`, `cmd`, `params`, `crc`,
`next`; кольцевой буфер - Python `collections.deque` на хосте и
массив в COMMON на Fortran.

### 3.4 Прерывания и тактирование

- маска событий `=20 2417`, `2Р — прерывание от СМ-2` (`dog2:150-160`);
- `*SYSTEM*`: часы, минуты, секунды, номер шага (`dog2:112-118`);
- `TIME(6) .ВРЕМЯ ОТ Э-60` (`src/ps/ps_src.txt:67`);
- `PERIOD` в описателе блока и счётчики `CNT ПС1..4`.

В «Глиссаде»: `NSTP` и `DTSH` уже есть в `/GLOB/`; добавить `GLTIME`
с масштабами (1 / 0,1 / 10) и очередью событий — это этап 10 плана тренажёра.

## 5. Что использовать готовым

1. **Тест СМ-2** `re-mrv/src/sm2_test/` — приёмочный тест для порта
   `hp2100`→СМ-2 и для проверки контракта пакетов (уже 0 ошибок, `E50=0`).
2. **Сводка** `re-mrv/src/integration/mrv_all.txt` (50 модулей) — готовый
   архитектурный шаблон; запускалась с `КОНЕЦ ЗАДАЧИ`, `E50=0`.
3. **Механика PERSO** из `re-glissade`: `TOOLS/build-dialog.py <work> 4000`
   и запись в зону 4000(8) — если подсистемы не помещаются в 2700(8),
   выносим их туда.
4. **Семафор `OKNO`** (`mrv_core.txt:35`, вызовы из DOG/WRI/REA/DEB/PS) —
   прототип хост-лока для доступа к пульту инструктора и пульту пилота.

## 6. Риски и GAP

- Эмулятора СМ-2 в `re-mrv` нет; наш порт в `simh` имеет GAP с кодировкой
  (`sm2_params.h`), поэтому тест связи проверяет сторону БЭСМ-6, а не ISA.
- Не расшифрованы PROMON (стр.50), `OKNO` как `NAME`, `TABNAS/TAROYA`,
  `HD PS2–PS5`, Fortran DEB — их роли берём только по описанию.
- Расхождения имён не домысливать: `RQTOCMD` vs `RQTOCM/ROTOCMD`,
  `CNT ПС1..4` vs `CNTPC1..4`, `ОНЕГА` vs `ОМЕГА`.
- Диспак не поддерживает многопроцессорность — «подчиненные задачи»
  моделируются очередью событий в Pascal и хост-процессами.
- Латинская `Y` в командах превращается в кириллическую `У` — имена
  новых команд проверять по этому правилу.

## 7. Связь с планом тренажёра

Данный план дополняет `docs/PLAN-TRENAZHER-K71.md`: этапы P0–P7
реализуют уровень СОИ/СПД и часть ПВС, тогда как этапы 1–9 тренажёра
уже закрыли ТОР и ЦВС. Этап 10 (масштабы времени и event queue)
совпадает с P5 и должен выполняться первым из новых.
