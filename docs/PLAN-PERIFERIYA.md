# ПЛАН ПЕРИФЕРИЙНЫХ ПОДСИСТЕМ ТРЕНАЖЁРА «ГЛИССАДА-6»

Дата: 19 ноября 2026 года. Составлен по разбору `/home/azizz/Yandex.Disk/re-mrv`
(реконструкция СПО К-71 по `СПО_тексты.pdf`, 335 стр., МАДЛЕН 1.10.72).

**Ключевое уточнение (19.11.2026):** задачи ПВС должны **исполняться на СМ-2**,
а не в хостовых процессах. Хост только переносит данные и задаёт темп.

## 1. Цель и принцип

В К-71 периферийная вычислительная система состояла из вычислительных
комплексов **СМ-2**; на них крутились модели подсистем (`PS`, `СБОР 1–4`,
`HD PS1`), а БЭСМ-6 была центральной машиной. Доступ к периферии шёл через
КАДОПАМ/КРК/ДКС.

В «Глиссаде» это отображается так:

- **ЦВС** — `GLDIAL` + Fortran-ядро в PERSO зоне 2700 (как есть);
- **ПВС** — задачи на **эмулируемой СМ-2** (`../simh`, ветка `sm2-port`,
  слита в `master`): модели подсистем самолёта, приём команд, перекодировка;
- **СОИ/СПД** — обмен между БЭСМ-6 и СМ-2 через контроллер «Сопряжение 2К»
  `hp2100_sm2k.c` и хостовый драйвер;
- **ТОР** — пульт пилота/инструктора, `PASRED`, поле варианта C.

Хост **не моделирует** подсистемы — он их только перевозит и тактирует.

Источник ролей в `re-mrv`: DOG `src/dog/dog2_compilable.txt`, REA
`src/rea/rea_src.txt`, WRI `src/wri/wri_src.txt`, RCD `src/rcd/`, WCD
`src/wcd/`, M7B `src/m7b/`, PS `src/ps/`, DEB `src/deb/`.

## 2. Разделение ролей между машинами

| Роль | Где исполняется | Реализация |
|---|---|---|
| Главная задача, маска событий, режимы PIL/INS | БЭСМ-6 | `GLDIAL.CMDLOOP` |
| Приём пакета, проверка КС, распределение | **СМ-2** | задача `RCV` (аналог REA) |
| Выдача пакетов, кольцевой буфер | **СМ-2** | задача `SND` (аналог WRI) |
| Перекодировка приёма/выдачи | **СМ-2** | задачи `RCD`/`WCD` |
| Модели подсистем, `PERIOD`, счётчики | **СМ-2** | задачи `PS1…PS4` (аналог PS) |
| Время от Э-60 | **СМ-2** | задача `TIME` (`TIME(6)` в `ps_src.txt:67`) |
| Мост форматов | **СМ-2** | `GLXCOD`-эквивалент (аналог M7B) |
| Диагностика, дебрифинг | БЭСМ-6 | `GLDIAL.SCR` + `GLDEB` |
| Транспорт пакетов и тактирование | хост | `TOOLS/timeline.py`, `simh` |

Существующие `GLRECF`, `GLSCORE`, `GLFAULT` остаются на БЭСМ-6 и
встраиваются в обмен: регистратор получает `X,U,T`, оценка — метрики,
отказы — коды вводных.

## 3. Среда СМ-2 и её ограничения

Эмулятор: `../simh`, `SET CPU SM2` / `SET CPU SM2M`, память до 128К слов,
устройство lines `SM2K` (`SET SM2K SC=…`, регистры `SM2KD`, `SM2KF`).
Готовый набор команд — в `HP2100/hp2100_cpu8.c`, кодировка объявлена в
`HP2100/sm2_params.h`.

**GAP: точные битовые раскладки кодов СМ-2 в источнике отсутствуют.**
Рабочая кодировка `SM2_OP_*` — наша декларация. Поэтому задачи, которые мы
пишем, гарантированно работают на нашем эмуляторе, но **несовместимы с
подлинной СМ-2** до дизассемблирования `АД01`/модулей из архива `LIBR1`
диска 2248. Это надо честно указывать в отчётах.

Сборка задач: пока ручная — machine words через `DEPOSIT` в SIMH; при
необходимости пишется минимальный ассемблер под объявленную кодировку.

## 4. Контракты данных (из `re-mrv`)

### 4.1 Дескриптор блока (7 полей)

```
*0 A BLOCK   — адрес начала блока      *4 LENG  — длина в словах
*1 NUM PS    — номер подсистемы        *5 C NUMB — номер блока
*2 A PROG    — адрес программы         *6 PERIOD — интервал шагов
*3 A TABL    — адрес таблицы
```

Передаётся как поле пакета; на СМ-2 — адрес в памяти задачи, на БЭСМ-6 —
record Pascal / COMMON Fortran (`IBLK, IPS, IPROG, ITABL, ILEN, INUM, IPER`).

### 4.2 Формат таблицы выдачи

```
F,ZKK,<имя переменной>   F=00 — одно число; F≠00 — массив до 16 слов
KK = 1:37(8)             интервал шагов
:Z00, / ,Z00,            конец таблицы
```

### 4.3 Пакет и кольцевой буфер

Четыре пакета: Э-60/хост + три СМ-2, связанных ссылкой `NEXT PCT`
(`dog2:820-823`). Поля: `NNM=6`, `N PACK=11`, `BEG COM=12`. Блок команд:
`−0` код (`=0` конец), `−1` число параметров, `−N+2` контрольная сумма,
`−N+3` код следующей команды. Чтение двухфазное: сначала сумма, потом
исполнение (`dog2:812-819`). Признак конца — `*50,IN E50`.

Слово кольцевого буфера: разряды 1–15 — адрес следующего слова, 16–31 —
код сообщения (`wri:498-519`).

### 4.4 Прерывания

Маска `=20 2417`, `2Р — прерывание от СМ-2` (`dog2:150-160`), декодер
`SWITCH` (`:250-273`). У нас: команда пилота/инструктора становится
событием с кодом источника, приоритет — по номеру, как `2Р`.

## 7. Риски и GAP

- Кодировка СМ-2 объявлена, не сверена с железом — главный GAP.
- Эмуляция СМ-2 не имеет подлинной ОС и системных программ; задачи пишем сами.
- Диспак не поддерживает параллельные задачи — «одновременность» ПВС
  создаётся очередью событий и темпом хоста.
- `re-mrv` не расшифровала PROMON (стр.50), `TABNAS/TAROYA`, `HD PS2–PS5`;
  их роли берём только по описанию.
- Расхождения имён не домысливать: `RQTOCMD` против `RQTOCM/ROTOCMD`,
  `CNT ПС1..4` против `CNTPC1..4`.
