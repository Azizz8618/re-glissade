# АЛФАВИТНО-ЦИФРОВОЕ ИГРОВОЕ ПОЛЕ ДЛЯ ОТЛАДКИ В DISPAK

Документ описывает текстовое представление игрового поля «Глиссады-6»,
которое печатается на АЦПУ и может отлаживаться в пакетном эмулятореДиспак
без МС-7401. Дата: 18 ноября 2026 года.

---

## 1. Что есть сейчас

`SRC/GLOUT.FTN`, подпрограмма `FRAME`: кадр из четырёх строк чисел
(`T, DALN, VYS`, `SKOR, VERT, ATAKA, TYAG`, рули/углы) и одной строки
индикатора глиссады — 41 позиция по 5 м, звездочка в позиции `IPOS`.

Недостаток: нет пространственного представления — полосы, глиссады,
самолёта. Для отладки диалоговой версии нужно «игровое поле».

---

## 2. Режим `ТЕЛЕ^` — основа алфавитно-цифрового дисплея

Директива `ТЕЛЕ^` в паспорте задачи (размещается после `ШИФР`, перед
`EEВ1А3`) устанавливает `psp.tele = 1` (`DISPAK/vsinput.c:270-277`).
ТогдаДиспак работает как **интерактивная задача** (`dispak.c:380-387`):
- вывод на терминал (АЦПУ/видеотон) включается по умолчанию;
- `pout_enable` управляется флагом `-p`;
- ввод идёт с логического устройства terminate (канал 5/терминал).

Готовые примеры колод с `ТЕЛЕ^`: `simh/BESM6/VVOD/vvod_dubna.txt`,
`zka_test.txt`. Формат паспорта: `ШИФР 410300^ / ОЗУ 32^ / ТЕЛЕ^ /
tap 60(2148)^ / дис 57(2048)^ / АЦП 128^ / ВХО 1^ / ВРЕ 1^ / ЕВ1`.

**Вывод:** вДиспак текст задачи печатается в stdout (`run.out`) и,
при включённом `-p`, в output-поток. Для отладки достаточно `run.out`
и `TOOLS/decode_printfile.py`; графический `dd.m20` и МС-7401 не нужны.

**Ввод:** команды оператора подаются как карты после `*execute`
(штатный путь монитора, `PRVIN` в `GLAUTO.FTN`), либо через
терминальную сессию ДКС (если запускать под simh с `set ttyN dks,raw`).
Для отладки в пакетномДиспак проще всего — карты.

**Уточнение по выводу (субагент):** в игровой колоде `WRITE(6)` идёт
не в stdout, а через МОНА-80-спул → Э70 `u=46` → барабан 020 →
`--drum-dump=dd` → `TOOLS/decode_print_glis1r.py dd.m20 4 7`.
`run.out` содержит только листинг трансляции — кадров там нет.
Канал 12 (`WRITE(12)`) в пакетномДиспак физического дисплея не имеет;
использовать его как надёжный вывод **не следует**.

**Четыре разных пути ввода/выводаДиспак:**

| Путь | Механика | Когда использовать |
|---|---|---|
| E64 → stdout | `print()` (`extra.c:657`), batch `pout_enable=1` | простые задачи/пультовые программы |
| МОНА-спул → `dd.m20` | `WRITE(6)` → Э70 `u=46` → барабан 020 | **игра `GLIS1R` — рабочий путь** |
| Э71 `fgets(stdin)`| `ttin()/ttout()` (`extra.c:2436,2334`), нужен `ТЕЛЕ^` и `-p` | «живой» псевдодиалог, без ДКС |
| карты → `seed-k12.bin` | `TOOLS/mk_seed_k12.py`, барабан 020/04 | сценарный диалог (этап 1) |

`BESM6_LUN_TAIL=06` — redirect ЛУН 47–57 на пустой лист, **не имеет
отношения к каналу 12**. `BESM6_EXIT_ADDR` — локальный патч `eexit()`,
в исходникахДиспак отсутствует; на печать не влияет (Э62 6 не
обслуживается мини-супервизором). `BESM6_LUN45_NATIVE` не включать
(ошибка 201). `BESM6_LUN45_EXECUTE` в чистом прогоне убран как вредный.

## 3. Архитектура текстового варианта

Pascal — ведущая программа `GLDIAL`, Фортран — ядро (все `SRC/GL*.FTN`
кроме `GLMAIN`). Ядро вызывается через `PROCEDURE ...; FORTRAN;` с
VAR-параметрами по ссылке (мост `P/MF`).

Что делает Pascal: меню, ввод параметров, приказный цикл, шаг РК4
(4 вызова `PROIZV`), печать кадра `WRITELN`, синхронизация COMMON
через 6 аксессоров `GLACC.FTN` (`GLSET`, `GLSOST`, `GLBUR`, `GLSC`,
`GLVOD`, `GLANG`). `FRAME` вызывается только для побайтовой сверки
(режим `ICTRL=9`), штатно — нет. `JUDG` остаётся в Фортране.

Три транспорта команд: `PASRED` (терминал, `ICTRL=1`), карты с
канала 5 (`INPUT`), встроенный сценарий (для регрессии).

## 4. Каркас текстового игрового поля

Кадр (`PRFRM`) повторяет `GLOUT.FTN:30-46`, но печатается Pascal:

```pascal
PROCEDURE PRFRM;
VAR I:INTEGER;
BEGIN
  GLANG(X,TH,GA,PS,DTM,EGLI,IPOS);
  GLVOD(VA,ALFA);
  WRITELN;
  WRITELN('GLISSADA  T=',T:7:1,' S DALN=',DTM:7:0,' VYS=',X[13]:8:1);
  WRITELN('SKOR=',VA:6:1,' M/S VERT=',X[2]:7:2,' M/S',
          ' ATAKA=',ALFA:5:1,' GR TYAG=',100*U[4]:4:0,' PRC');
  WRITELN('RV=',U[1]*RAD:6:1,' GR EL=',U[2]*RAD:6:1,' GR',
          ' RN=',U[3]*RAD:6:1,' GR TANG=',TH:6:1,' GR',
          ' KREN=',GA:6:1,' GR KURS=',PS:6:1,' GR');
  WRITELN('                 GLISSADA 3 GR.');
  FOR I:=1 TO 41 DO LN[I]:=' ';
  LN[IPOS]:='*';
  WRITE('                 ');
  FOR I:=1 TO 41 DO WRITE(LN[I]);
  WRITELN;
  WRITELN('KURS LUCH  Y=',X[12]:7:1,' M  GLIS=',EGLI:7:1,' M');
  WRITELN
END;
```

Строка звёздочки — 41 позиция по 5 м, центр 21, `IPOS` из `GLANG`
(формула `GLOUT.FTN:24-29`). Это и есть алфавитно-цифровое поле:
полоса (индикатор), текущее отклонение, числовые параметры.

### Выбранный формат — вариант C (комбинированный)

Решение пользователя (18 ноября 2026 года): печатает **Pascal-программа**,
поле — **вариант C**: профиль захода + план сверху + две шкалы.
Фортранный `FRAME` в штатном режиме не вызывается.

Макет (профиль слева, вид сверху справа, две шкалы внизу):

```
T= 140.0 TIP=3 TU-104 AVTO  DALN= 3641 VYS= 177.9 Y=-105.1
 ВЫС  ПРОФИЛЬ              | ПЛАН СВЕРХУ
 800 |                   . |     |====|
 700 |                .    |     | *  |
 600 |             .       |     |    |
 500 |          .          |     |====|
 400 |       .             |    OSEVA
 300 |     .   *           |
 200 |   .                |
 100 |.                    |
   0 |===|===|===|===|ВПП |
      15km  10km  5km  0
 GLISS 3 GR |----*----| EGLI=  -9.3 M
 KURS LUCH |----*----| Y=  -105.1 M
 SKOR= 76.5 VERT= -3.35 ATAKA= 1.0 TYAG= 43 PRC
 OCENKA= 3 UDOVLETVORITELNO
```

Обозначения: полоса `=`, порог `|`, глиссада `.`, самолёт `*` (выше
глиссады `+`, ниже `-`), план — вертикальная полоса со сносом по `X(12)`.
Шкалы — 41 позиция по 5 м, центр 21 (`GLANG` даёт `IPOS`, `GLVOD` —
`ALFA`). Всё — 7-битные символы, совместимые с Холлеритом.

### Pascal-процедура печати (вар. C)

```pascal
PROCEDURE PRFRM;
VAR I,J,IH,JA,JG,IB:INTEGER; HGL:REAL;
BEGIN
  GLANG(X,TH,GA,PS,DTM,EGLI,IPOS);
  GLVOD(VA,ALFA);
  IB:=21+IFIX(X[12]/5.);
  IF IB<1 THEN IB:=1; IF IB>41 THEN IB:=41;
  WRITELN;
  WRITELN('T=',T:7:1,' TIP=',KTIP:1,' DALN=',DTM:7:0,
          ' VYS=',X[13]:7:1,' Y=',X[12]:7:1);
  WRITELN(' VYS PROFILE              | PLAN SVERHU');
  FOR IH:=8 DOWNTO 0 DO
  BEGIN
    WRITE(' ',IH*100:4,' |');
    FOR J:=1 TO 30 DO
    BEGIN
      HGL:=0.05241*(31-J)*500.0;
      JA:=31-IFIX(DTM/500.0);
      IF (IH=IFIX(X[13]/100.0)) AND (J=JA) THEN WRITE('*')
      ELSE IF IFIX(HGL/100.0)=IH THEN WRITE('.')
      ELSE IF IH=0 THEN WRITE('=')
      ELSE WRITE(' ')
    END;
    WRITE(' |');
    IF IH=8 THEN
      BEGIN WRITE('    |====|'); FOR J:=1 TO IB DO WRITE(' ');
            WRITE('*'); WRITELN END
    ELSE IF IH=0 THEN WRITELN('    |====|')
    ELSE WRITELN('    |    |')
  END;
  WRITELN('      15km  10km  5km  0');
  WRITELN(' GLISS 3 GR  |----*----| EGLI=',EGLI:7:1,' M');
  WRITELN(' KURS LUCH  |----*----| Y=',X[12]:7:1,' M');
  WRITELN(' SKOR=',VA:6:1,' VERT=',X[2]:6:2,
          ' ATAKA=',ALFA:5:1,' TYAG=',100*U[4]:3:0)
END;
```

Замечание: `GLANG`/`GLVOD` — аксессоры `GLACC.FTN` (см. раздел 3);
`DTM=-X(11)` — дальность до порога. Символ самолёта в профиле ставится
в столбец `JA` и строку `IFIX(X[13]/100)`, глиссада — точками по
`HGL=0.05241·DALN`.

## 5. Словарь команд диалога (этап 2 плана тренажёра)

Команда — `'ALFA'`, то есть ровно 6 литер в коде ГОСТ 10859. Недостающие
позиции дополняются пробелами (`GTALF`). Сравнение — `CMD='STA   '`.
Все команды — латиницей, заглавные; кириллица в командах не применяется,
чтобы не смешивать кодировки АЦПУ и видеотона.

### 5.1 Пилот (режим `PILOT`)

| Команда | Аргумент | Действие | Этап |
|---|---|---|---|
| `STA` | — | непрерывный счёт до касания/лимита/`STO` | готово |
| `STE` | — | один шаг РК-4 + печать кадра | готово |
| `STO` | — | пауза | готово |
| `PAR` | — | повторный ввод параметров + сброс | готово |
| `PRN` | — | печать кадра без продвижения времени | готово |
| `EXIT` | — | выход | готово |
| `AUTO` | — | вернуть управление автопилоту | 5 |
| `EV+` / `EV-` | — | руль высоты ±0,05 рад | 5 |
| `AI+` / `AI-` | — | элероны ±0,05 рад | 5 |
| `RU+` / `RU-` | — | руль направления ±0,05 рад | 5 |
| `TH+` / `TH-` | — | тяга ±0,05 | 5 |

### 5.2 Инструктор (режим `INSTR`)

| Команда | Аргумент | Действие | Этап |
|---|---|---|---|
| `SEL` | номер упражнения | выбрать упражнение из библиотеки | 3, 4 |
| `FRZ` | — | заморозить расчёт | 3 |
| `UNF` | — | снять заморозку | 3 |
| `INJ` | код отказа | ввести отказ/аварийную вводную | 6 |
| `REC` | — | начать запись X(13), U(4), T | 7 |
| `PLY` | — | воспроизвести запись | 7 |
| `RST` | — | сброс к исходному состоянию упражнения | 7 |
| `SCR` | — | показать оценку задания (дебрифинг) | 8, 9 |
| `HLP` | — | список команд | 3 |
| `PIL` / `INS` | — | переключение режима пилот/инструктор | 3 |

### 5.3 Правила ввода

- Аргумент запрашивается отдельным приглашением PASRED сразу после
  команды; формат — целое (`SEL`, `INJ`) в диапазоне, указанном в
  справке `HLP`.
- Неизвестная команда печатает `NEPR. KOMANDA` и не меняет состояние.
- Команды пилота доступны только в режиме `PILOT`, инструктора — только
  в `INSTR`; переключение режимов — `PIL`/`INS` (этап 3).
- Все новые команды добавляются в `CMDLOOP` через тот же `SELECT`, что
  и существующие; 6-литерные литералы не должны содержать Ё или
  строчные буквы.

## 6. Этапы внедрения

| Шаг | Работа | Критерий |
|---|---|---|
| 0 | Минимальная `PROGRAM M` вДиспак, лист загрузки: мост `P/MF`, COMMON | нет неопределённых имён |
| 1 | `GLACC.FTN` (6 аксессоров) | сборка `*FORTRAN` проходит |
| 2 | Каркас `GLDIAL`: меню, `PARAMS`, `PASRED`, разбор чисел | меню печатается, эхо параметров |
| 3 | `INIT` + `DOSTP` (РК4), дамп `DBG` первых 3 шагов | `T=0.1/0.2/0.3`, X совпадает с эталоном |
| 4 | `RUN` + `PRFRM`, команды `STA/STO/PRN` | кадры `T=140/145/150/175` в пределах ±0.11 |
| 5 | `GLSC` → `JUDG`, остановы | `OCENKA=3`, `VERT=-3.67`, `ТОЧКА=-4` |
| 6 | Три транспорта команд | одинаковый `DBG`-лог |
| 7 | Регрессия по числовым токенам `RUNS/run-2026-11-17-clean/` | расхождения зафиксированы |
| 8 | Одна колода: `*CALL *PASCAL` + `*FORTRAN` + `*EXECUTE` | кадры только на АЦПУ, без МС-7401 |

**Стоп-условие:** если шаг 0 не подтвердил COMMON-мост — вернуться к
`docs/PLAN-DIALOG.md` и не писать цикл «вслепую».
