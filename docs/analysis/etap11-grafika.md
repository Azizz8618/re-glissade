# ЭТАП 11. ХОСТ-РЕНДЕР КАДРОВ ВАРИАНТА C

Дата: 19 ноября 2026 года.

## 1. Суть этапа

Создан хост-драйвер, который прогоняет эталонную программу
`mc-7401/golden/graf.pas` на трансляторе Паскаля-Монитора, снимает поток
команд в линию и рисует кадр эмулятором терминала «Электроника МС 7401».
Проект `mc-7401` используется только как зависимость: его файлы читаются
и импортируются, но не изменяются.

Контрольная точка этапа — побайтовое совпадение потока с эталонными файлами
`mc-7401/golden/streams/<сценарий>.bin`.

## 2. Как запускать

Из корня репозитория `re-glissade`:

```
python3 TOOLS/graf_driver.py verify
python3 TOOLS/graf_driver.py verify ЗАГ СЕТ СОЛ
python3 TOOLS/graf_driver.py render ЗАГ
python3 TOOLS/graf_driver.py frame params.json
python3 TOOLS/graf_driver.py list
```

Назначение действий:

- `verify` — снять потоки всех сценариев и сверить их с эталонами;
  при указании имён проверяются только они;
- `render <сценарий>` — сохранить поток и кадр в каталог `TOOLS/graf`;
- `frame <файл параметров>` — прочитать словарь параметров кадра игры,
  сформировать ввод для `graf.pas`, сохранить поток `frame.bin` и кадр
  `frame.png`;
- `list` — перечень сценариев с описаниями.

Дополнительные ключи: `--scale` задаёт масштаб изображения, `--out` задаёт
путь кадду. Путь к внешнему проекту можно задать переменной среды
`MC7401_ROOT`; по умолчанию драйвер ищет каталог `mc-7401` рядом с этим
репозиторием.

Тесты:

```
python3 -m unittest discover -s TOOLS/tests -p 'test_graf_driver.py' -v
```

## 4. Как stream_from_game_frame отображает параметры игры

`graf.pas` получает на вход не числа модели полёта, а текст приказов
оператора. Подпрограмма `ПРИКАЗ` читает трёхлитерное имя, подпрограммы
`ТАКЕ` и `СТАКЕ` читают десятичные числа после некоторых приказов.
Поэтому отображение построено так.

| Что передано в словаре параметров | Что делает драйвер | Статус |
|---|---|---|
| ключ `приказ`, `команда` или `сценарий` с именем из таблицы | берёт этот приказ как есть и ставит после него пробел | подтверждено, по тексту graf.pas |
| ключ `числа`, `аргументы` или `параметры` со списком целых | дописывает числа через пробел после приказа | подтверждено, graf.pas читает числа подпрограммами ТАКЕ и СТАКЕ |
| приказ из списка ГРА, ОКР, ЛИН, ТИП, ЧАС, КИН, КИНО, ПТИ | разрешает числовые аргументы | подтверждено, по тексту graf.pas |
| приказ без числовых аргументов вместе с числами | отклоняет запрос с сообщением об ошибке | подтверждено, graf.pas не читает числа после такого приказа |
| неизвестный приказ | отклоняет запрос через исключение | подтверждено |
| поля `T`, `DTM`, `X`, `VA`, `ALFA`, `U`, `THETA`, `GAM`, `PSI`, `EGLI`, `VERT`, «отклонение», «тип самолёта», «скорость», «время» | заносит в список неподтверждённого; на поток не влияют | GAP |
| явного приказа нет | по соглашению драйвера берёт `СЕТ` и помечает это как GAP | GAP, соглашение драйвера |

Схема меток в таблице выше означает: `подтверждено` — соответствие прямо
следует из текста `graf.pas`; `GAP` — соответствия в эталонной программе нет.

Пример. Словарь `{'приказ': 'ГРА', 'числа': [5]}` даёт ввод
`ГРА 5 ВЫХ ` и поток из 383 байт. Словарь `{'T': 12.5, 'VERT': 3,
'скорость': 280}` даёт ввод `СЕТ ВЫХ `, поток равных 2994 байтам сценария
`СЕТ`, а в плане драйвера перечислены три поля, которые не имеют входа
в `graf.pas`.

## 5. Как связать с игрой

Путь обработки кадра варианта C:

1. Ядро `GLOUT.FTN` и Fortran-модули выдают переменные кадра
   `T, DTM, X(13), VA, X(2), ALFA, U(4), THETA, GAM, PSI, EGLI`.
2. Хост-процесс этапа 10 доставляет их как событие задаче-получателю
   через очередь; драйвер читает словарь параметров.
3. `GrafDriver.game_frame_plan()` раскладывает словарь на приказ graf.pas
   и честный список GAP.
4. `GrafDriver.stream_from_game_frame()` прогоняет `graf.pas` и возвращает
   поток байт.
5. `GrafDriver.render()` отдаёт поток эмулятору `mc7401`, выбирает самый
   наполненный кадр и сохраняет изображение.

Так сохраняется архитектурная аналогия КАДОПАМ из плана: драйвер не печатает
лог, а доставляет кадр дальше по конвейеру. Реальные масштабы времени
остаются на стороне хоста (этап 10).

## 6. Честный GAP

- **Физического соединения нет.** МС-7401 не входил в К-71 и физически не
  подключён к БЭСМ-6. Он стоит на стороне Электроники-60 (МИДИКОН).
  В симуляторе Диспака эмулируется только текстовая линия ДКС, а не поток
  графики. Графика БЭСМ-6 — это экстракоды Э50 1200…1207, другое устройство.
- **Графический канал — только хост-рендер.** Поток снимается с
  транслированного на хосте `graf.pas` и рисуется эмулятором `mc7401`.
  Никакой записи в устройства БЭСМ-6 не производится.
- **Обработка `ВЫД`/`РИС` взята из `graf.pas`.** Драйвер не переписывал
  эти подпрограммы: он исполняет транслированный текст эталонной программы,
  поэтому ВУК-обвязка, принудительная выдача и `REWRITE(OUTPUT)` работают
  так же, как в эталоне. Это подтверждено совпадением всех девятнадцати
  потоков.
- **Кадр приборной доски не воспроизведён.** Картинка «полоса ВПП, осевая
  пунктиром, глиссада три градуса, самолёт-крест, шкала отклонения» из
  раздела 6, пункт 3 плана диалога ни одним приказом `graf.pas` не рисуется.
  Упомянутый там проверенный минимальный кадр в 206 байт и 21 команду
  относится к другой, специально собранной программе; в эталонных потоках
  `mc-7401` его нет. Для него нужна отдельная Pascal-программа на базе
  `НАЧГРАФ`, `ЛИНА`, `РАМКА`, `ТЕКСТ`, `ВЫД`/`РИС`.
- **Параметры полёта не управляют рисунком.** В `graf.pas` нет входных
  переменных для времени, скорости, высоты, вертикального отклонения и типа
  самолёта. Любое «правдоподобное» соответствие вроде «отклонение — это
  радиус окружности» было бы выдумкой, поэтому в драйвере его нет.
- **Выбор `СЕТ` по умолчанию — соглашение нашего драйвера**, а не свойство
  терминала или исторический факт. Он нужен только для того, чтобы вызов
  с неполным словарем параметров всё же давал воспроизводимый кадр.
- **Нет реального времени и звука.** Это отдельные этапы 10 и 12.
