# Изменение конфигурации самолёта в полёте

Дата: 19 ноября 2026 года. Источник приращений — сводка
`docs/analysis/konfiguraciya-svod.md`, раздел 3, и разведывательный
отчёт `docs/analysis/osint-konfiguraciya-mig15-il28.md`.

Пометки в тексте: **[Д]** — прямо указано в документе, **[Г]** — прочитано
с графика, **[Р]** — расчёт по документным числам, **[О]** — оценка.

## 1. Команды инструктора

В режиме `INS` добавлены три команды. Число вводится после запроса `>`
через `GTINT`, диапазон проверяется, при ошибке старое состояние
восстанавливается из Фортрана вызовом `CFGET`.

| Команда | Значение | Смысл | Подтверждение |
|---|---|---|---|
| `FLP 0` | 0 | закрылки убраны (база) | ЗАКРЫЛКИ: УБРАНЫ |
| `FLP 1` | 1 | взлётные закрылки | ЗАКРЫЛКИ: ВЗЛЁТНЫЕ |
| `FLP 2` | 2 | посадочные закрылки | ЗАКРЫЛКИ: ПОСАДОЧНЫЕ |
| `GER 0` | 0 | шасси убрано | ШАССИ: УБРАНО |
| `GER 1` | 1 | шасси выпущено | ШАССИ: ВЫПУЩЕНО |
| `SPL 0` | 0 | спойлеры убраны | СПОЙЛЕРЫ: УБРАНЫ |
| `SPL 1` | 1 | спойлеры выпущены | СПОЙЛЕРЫ: ВЫПУЩЕНЫ, ОЦЕНКА |

Вне диапазона печатается `ОШИБКА: FLP 0/1/2`, `ОШИБКА: GER 0/1`
или `ОШИБКА: SPL 0/1`. Списки команд в `CMDLOOP` и `HLP` дополнены.
Подтверждение «ОЦЕНКА» в `GLDIAL.PAS` сохранено без изменения:
режим теперь имеет физический смысл только у МиГ-15, у остальных
типов он нейтрален (см. раздел 6).

## 2. Структура

- `SRC/GLCONF.FTN`, блок `BLOCK DATA GLCONF`:
  - `/CONFG/` — переключатели `IFLAP`, `IGEAR`, `ISPOI`,
    начальное значение нули;
  - `/CFDEL/` — приращения `DL0(5,2)`, `DLMX(5,2)`, `DD0(5,2)`,
    `DCM0(5,2)`, `DCLA(5,2)`, `DG0(5)`, а также новые массивы
    спойлеров `DCLS(5)`, `DCDS(5)`, `DCMS(5)`;
  - `/CFALF/` — эффективный угол срыва `ALFSEF`.
- `SRC/GLCONF.FTN`, подпрограмма `CFUPD` — пересчёт эффективных
  коэффициентов и угла срыва; вызывается в начале `PROIZV`
  из `SRC/GLPROIZ.FTN`.
- `SRC/GLCONF.FTN`, `CFSET` и `CFGET` — запись и чтение
  переключателей из Паскаля.
- `SRC/GLPROIZ.FTN` — берёт порог сваливания из `/CFALF/` вместо
  прямой константы `TALFS(KTIP)`.
- `SRC/GLDIAL.PAS` — команды, подтверждения и строка `KONF` в кадре.
- `TOOLS/build-dialog.py` — `GLCONF` добавлен в список `CORE`,
  чтобы блок данных и подпрограммы попали в ядро PERSO.

Порядок типов во всех массивах: 1 МиГ-15, 2 Ил-28, 3 Ту-104,
4 Ан-24, 5 Ан-2. Второе измерение массивов — конфигурация:
1 взлётная, 2 посадочная.

## 3. Формула

На каждом вызове `CFUPD` сначала берётся точная база из `/TTXDAT/`,
затем прибавляются приращения:

```
CL0  = TCL0(KTIP)  + DL0(KTIP,IFLAP)
CLA  = TCLA(KTIP)  + DCLA(KTIP,IFLAP)
CLMX = TCLMX(KTIP) + DLMX(KTIP,IFLAP)
CD0  = TCD0(KTIP)  + DD0(KTIP,IFLAP)
CM0  = TCM0(KTIP)  + DCM0(KTIP,IFLAP)
```

Далее, если выпущено шасси, `CD0 = CD0 + DG0(KTIP)`.
Если выпущены спойлеры, приращения берутся по типу:

```
CL0 = CL0 + DCLS(KTIP)
CD0 = CD0 + DCDS(KTIP)
CM0 = CM0 + DCMS(KTIP)
```

Наконец, пересчитывается эффективный угол срыва:

```
ALFSEF = (CLMX - CL0) / CLA
```

Пересчёт от базы, а не от прежнего значения `/SOST/`, делает `CFUPD`
идемпотентным: повторные переключения и многократные вызовы внутри
РК-шага не накапливают приращения. Конфигурация 0 даёт точную базу
`GLINITD`, поэтому траектория эталонных прогонов не меняется.

## 5. Моментные приращения (исправление первого GAP)

Прежняя ошибка: у МиГ-15 в `DCM0` стояли `+0,01` (20°) и `+0,06`
(55°), то есть момент кабрирующий. По рисунку 61 книги Соголова
закрылки дают **пикирующий** момент: кривая при 20° лежит ниже
нулевой примерно на 0,06, при 55° — примерно на 0,12 [Г].
Знак исправлен на отрицательный, значения записаны по тексту
отчёта `osint-konfiguraciya-mig15-il28.md`, раздел 1.2, пункт 11.

| Тип | Конф. 1 | Конф. 2 | Статус | Обоснование |
|---|---:|---:|---|---|
| МиГ-15 | −0,06 | −0,12 | [Д/Г] | Рис. 61 Соголова: пикирующий момент 0,06 и 0,12 |
| Ил-28 | −0,01 | −0,05 | [О] | Знак уточнён по общему правилу; знак прямо в книге не подтверждён |
| Ту-104 | −0,03 | −0,07 | [О]/[Д] | Пикирующий момент подтверждён РЛЭ, величина оценочная |
| Ан-24 | 0 | −0,05 | [О] | Пикирующий момент по оценке сводки |
| Ан-2 | 0 | +0,08 | [О] | Кабрирующий момент, данные качественные, диапазон +0,05…+0,10 |

У Ил-28 посадочное значение уточнено с −0,04 до −0,05 по сводке;
у Ан-2 с +0,03 до +0,08 — середина качественного диапазона.
Взлётные значения остальных типов, а также нули Ан-24 и Ан-2
в конфигурации 1 оставлены без изменения: документированных чисел
для них нет.

## 6. Спойлеры по типам (исправление второго GAP)

Прежняя ошибка: в `CFUPD` для всех типов жёстко задавалось
`CL0 = CL0 − 0,3` и `CD0 = CD0 + 0,02` без источника.
Теперь приращения лежат в массивах `/CFDEL/` и выбираются по типу.

| Тип | DCLS | DCDS | DCMS | Статус |
|---|---:|---:|---:|---|
| МиГ-15 | 0 | 0,0225 | +0,05 | [Д/Г] Соголов, рис. 58 и 61 |
| Ил-28 | 0 | 0 | 0 | спойлеров нет [О] |
| Ту-104 | 0 | 0 | 0 | данных нет, GAP |
| Ан-24 | 0 | 0 | 0 | интерцепторов нет [О] |
| Ан-2 | 0 | 0 | 0 | спойлеров нет [О] |

Для МиГ-15 использованы данные из разведывательного отчёта: площадь
тормозных щитков 0,8 м² (выпуск 1952 года) [Д], коэффициент
сопротивления по рисунку 58 около 0,0225 [Г], кривая продольного
момента с щитками лежит выше кривой без них, то есть момент
кабрирующий [Г]. Подъёмная сила не создаётся, поэтому `DCLS(1)=0`.
Число 0,0225 по заданию заложено в модель как документное значение
графика; в отчёте отмечено, что он относится к площади 0,5 м²,
а масштабирование на 0,8 м² даёт около 0,035 — это отдельный GAP.

Для Ил-28, Ан-24 и Ан-2 в источниках спойлеров нет: команда `SPL 1`
для этих типов не имеет эффекта, коэффициенты не меняются.
Для Ту-104 данных тоже нет, массивы заполнены нулями и помечены
как GAP в разделе 9.

## 7. Угол срыва при смене конфигурации (исправление третьего GAP)

Прежняя ошибка: `GLPROIZ.FTN` брал `ALFS=TALFS(KTIP)` напрямую
из `/TTXDAT/`, поэтому порог сваливания не зависел от выпуска
закрылков. Введён блок `/CFALF/` с полем `ALFSEF`; `CFUPD`
пересчитывает его после всех коэффициентов по формуле из шапки
`GLTTX.FTN`, а `PROIZV` использует `ALFS=ALFSEF`.

Проверка воспроизведения штатного значения на МиГ-15:

```
(1,46 - 0,15) / 5,7 = 0,229825
TALFS(1)            = 0,2298
```

Остальные типы: Ил-28 `(1,57−0,20)/4,8 = 0,285417` против 0,2854;
Ту-104 `(1,35−0,22)/4,2 = 0,269048` против 0,2690; Ан-24
`(1,60−0,30)/4,6 = 0,282609` против 0,2826; Ан-2
`(1,95−0,72)/3,66 = 0,336066` против 0,3361. Все штатные значения
округлены до четырёх знаков, поэтому формула воспроизводит их
с точностью до 5⋅10⁻⁵, но не побайтово.

Чтобы выполнить требование побайтовой неизменности конфигурации 0,
`CFUPD` после расчёта по формуле в базовой конфигурации
(`IFLAP=IGEAR=ISPOI=0`) берёт табличный `TALFS(KTIP)` дословно.
При любом переключении действует формула, и порог срыва меняется
вместе с `CL0` и `CLMX`. Разница между формулой и таблицей
(~2,5⋅10⁻⁵ рад) проявляется только за порогом срыва, то есть
на нелинейном участке характеристики.

## 8. Результат

- `CL0`, `CLA`, `CLMX`, `CD0`, `CM0` в `/SOST/` пересчитываются
  из базы и приращений до расчёта подъёмной силы, сопротивления
  и момента в `PROIZV`.
- Порог срыва берётся из `/CFALF/` и теперь следует за конфигурацией.
- Спойлеры дают эффект только у МиГ-15; у остальных типов режим
  нейтрален.
- Кадр печатает состояние в левом столбце строки `REZERV`:
  `KONF F<цифра> G<цифра> S<цифра>`; разделитель `+` и ширина
  38 знаков сохранены.
- При конфигурации 0 приращений нет, `/SOST/` совпадает с базой
  `GLINITD`, а `ALFSEF` совпадает с `GLINITD`-ным `TALFS`, поэтому
  регрессия 10/10, 5/5 и контроль md5 должны сохраниться.
- Проверены длины строк (не более 72), имена (не более 6 литер)
  и согласованность объявлений общих блоков.

## 9. GAP

1. База в `GLTTX.FTN` не везде «чистое крыло»: `CLMX` МиГ-15
   совпадает с книжным максимумом при закрылках, а `CL0` и `CLMX`
   Ан-2 уже описывают посадочную конфигурацию. Поэтому приращения
   заданы от текущей базы, а не от физического чистого крыла.
2. Знак и величина моментных приращений у Ил-28, Ан-24 и Ан-2
   оценочные. Для МиГ-15 знак и величина прочитаны с рисунка 61
   с погрешностью до 0,02–0,03.
3. Значение `DCDS(1)=0,0225` соответствует площади щитков 0,5 м²;
   для модели 1952 года с площадью 0,8 м² отчёт даёт около 0,035.
   Масштабирование не введено по заданию.
4. У Ту-104 нет данных по спойлерам: массивы `DCLS`, `DCDS`, `DCMS`
   заполнены нулями, режим нейтрален.
5. Площадь крыла Ту-104 в модели расходится с документом;
   новые коэффициенты могут потребовать перекалибровки `GLAUTO`.
6. В пакетных колодах `JOB/GLKERN-2700.B6` и `JOB/GLISSADA.B6`
   Fortran-текст встроен в колоду. После правки `SRC/GLCONF.FTN`
   и `SRC/GLPROIZ.FTN` эти встроенные копии нужно пересобрать
   из исходников (`build-dialog.py` делает это для диалоговой
   сборки); в этом сеансе колоды не трогались — сборка
   и регрессия выполняются основным сеансом.
7. В базовой конфигурации `ALFSEF` берётся из таблицы `TALFS`,
   а не из формулы, из-за округления табличных значений до четырёх
   знаков. На нелинейном участке характеристики это даёт расхождение
   до 5⋅10⁻⁵ рад.

## Результат сборки и проверки (19 ноября 2026 года, до правок трёх GAP)

Колоды пересобраны, ошибок компиляции и трансляции 0. Каталог PERSO
содержит входы `CFUPD`, `CFSET`, `CFGET`, `*CONFG*`.

**Конфигурация 0 (по умолчанию):** приращения нулевые, регрессия
сохранена полностью — сценарии 10/10, упражнения 5/5, `replay.py verify`
даёт `md1=md2=41a846dde9548f5e9a29e8bf3eb4ca33`.

**Переключение в полёте:** прогон с командами `INS`, `FLP 2`, `GER 1`,
`SPL 1`, `STA` дал в кадре `KONF F2 G1 S1`; игра завершилась с `OCENKA=2`.
Для сравнения тот же заход в конфигурации 0 давал `OCENKA=1`, а углы
атаки по кадру отличаются — значит эффективные коэффициенты реально
пересчитываются, а не только меняется индикация.

После исправления трёх GAP сборка и регрессия в этом сеансе не
запускались по заданию; их выполняет основной сеанс.
