# п.18.16(1) — СПОЛ-выдача: диагностика (А2, сессия 13.11-15)

Вопрос плана: почему файл печати не печатается на АЦПУ после
«КОНЕЦ ЗАДАЧИ» (п.18.15(2) показал: вывод WRITE(6) лежит в спуле
u=20 тракт 5, но печати нет).

## Средство: имитация ПУСКа оператора

Останов `*74` на 00411 — аутентичное поведение ДИСПАК (машина стоит,
пуск кнопкой). В эмуляторе `eexit()` (extra.c) возвращал E_TERM —
конец прогона.

Патч `dispak/extra.c eexit()`: **BESM6_EXIT_ADDR** (восьмеричный
адрес) — вместо останова `JMP(адрес)` (помечено «А2 13.11-15
п.18.16(1)»). Сборка — ручная по флагам
`build/dispak/CMakeFiles/dispak.dir/flags.make` (cmake в среде падает).

## Правильная точка продолжения: 00412 (СС после останова)

- `BESM6_EXIT_ADDR=412`: МОНА-80 выполняет восстановительный блок
  00412–00420: загружает М1–М15 из области сохранения
  (02575, 0, 34227, 0, 01121, 01125, 11101, 02262, 0, 1, 01756,
  03074, 00411, 11043, 75402 — точно предостановной контекст
  диспетчера МОНЫ), обнуляет [00000], [00014], [00122].
- `BESM6_EXIT_ADDR=437` (сырой читатель записей потока) —
  ОТРИЦАТЕЛЬНЫЙ результат: чтение мусора за концом потока,
  «ОТСУТСТВУЕТ 0Р !L / (Z», СВОБОД 01000/01010, КОНТРОЛЬ КОМАНДЫ.

## Что МОНА делает после ПУСКа (ключевая находка)

На 00421: `Э62 5747(М12)` — финальный запрос к супервизору.

1. Операнд: М16 = 0o11043 = 5747 + [М12=0o3074]. Число 77627 в
   отладочном хуке `E62at` (cu.c) — СТАРОЕ М16: хук печатается до
   вычисления ИА в I_TRAP (cu.c:761 `reg[016] = ADDR(addr+reg[i_reg])`).
   Подтверждение: rte-77-обработчик МОНЫ (03663) сохранил М16=0o11043
   в ячейку 0o2254, а М13/М14/М15 = 0411/11043/75402 в 0o2253-55.
2. Слово операции: [0o11043] = 0o6. Зона 0o11000–0o11060 — таблица
   операций МОНЫ: пары «слово ФИО + код» (коды 1,2,3,4,5,6,7,9,11,16,25).
3. Обслуживание: C `e62()` не знает кода → E_UNIMP → errchk (cu.c:878)
   передаёт экстракод аутентичному BEMSH-супервизору (вход 100011).
   Итог: «нереал» → статус задания 3 → «Пока рано» — машина стоит.
   СПОЛ-выдача не выполняется.

## Механизм выдачи в аутентичном супервизоре (есть!)

`ekdisp.b6` (диск 2099), обработчик `э6241` = **Э62 41 «запрос
вых.потока»** (только АЦПУ):
- номер зоны потока — из паспорта задачи (`шзнмб+2`),
- чтение зон с диска (`вчоб` → `физур`),
- выдача «40-го листа» через ТБУФ; «такой зоны пока нет» = конец.

Но: МОНА вызывает Э62 с кодом 6 (не 41), а печать-процесса с Э62 41
в одно-процессной конфигурации мини-супервизора нет
(Mini-Supervisor.txt: единственный процесс, канал 41).

## Состояние файла печати

Спул цел и идентичен до/после рестарта (u=20 тракт 5):
```
 IA =      3     1     0     5     1
 B =    2400.00  7351.00     1.50     0.60
 READ OK
```

## Ответ на вопрос п.18.16(1)

Файл не печатается, потому что: (а) после КОНЕЦ ЗАДАЧИ машина
останавливается (нужен ПУСК); (б) при ПУСКе МОНА делает финальный
запрос Э62 с кодом операции 6, который мини-супервизор не обслуживает
(«нереал» → «Пока рано»); (в) штатный механизм выдачи (Э62 41) в этой
конфигурации никем не вызывается.

## Открыто (план продолжения)

1. Реверс БЕМШ-макросов уии/слиа/мода/пио по disp99.b6 — точная
   семантика диспетчера э62.
2. Что такое Э62 6: гипотезы — завершение МОНЫ либо запрос выдачи.
   Проверка на подлинных томах ДИСПАК (.be в upload/: disp70.be и др.)
   и по Мазному.
3. Если 6 = выдача: реализовать Э62 6 в e62() как спул-выдачу
   (механизм Э62 41) и получить печать на АЦПУ.
