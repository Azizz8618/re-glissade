# Адаптивный шаг в ручной игре: что изменено и как включать

Дата: 19 ноября 2026 года.

## 1. Что изменено на самом деле

Изменён только справочный текст в докстринге `TOOLS/play.py`. Логика
запуска не тронута: скрипт по-прежнему копирует колоду
`JOB/GLCALL-2700.B6` во временный каталог, поднимает псевдотерминал и
пробрасывает байты с клавиатуры прямо в задание. Он не подставляет
ответы на приглашения и не подменяет значения карт.

В частности, `play.py` **не задаёт ICTRL**. Значение вводит оператор
своими руками, поэтому «включить адаптивный шаг по умолчанию» в этом
скрипте невозможно без подстановки ответа за оператора. Такая
подстановка не делалась: она изменила бы характер ручной игры и
потребовала бы разбора потока приглашений.

Остальные файлы не трогались. Автоматические прогоны остаются на своём
фиксированном шаге: `run_gldial_pty.py` передаёт третьим ответом `0`,
а значит `scenarios.py`, `exercises.py` и `replay.py` по-прежнему
работают с `ICTRL=0`. Регрессия не проверялась заново и не изменялась.
Установку `install-2348.sh` и сборку не запускали.

## 2. Где оператор задаёт ICTRL

После заголовка `GLISSADA-6 / TEKSTOVY DIALOG` программа спрашивает
девять полей первого блока параметров (первой «карты» диалога). ICTRL —
**третье поле**, сразу после `TIP` и `MODE`. Запрос выглядит так:

```
> ICTRL 0 BATCH / 1 TERM :
-
```

После каждого запроса Pascal печатает одиночную литеру `-`; ответ
вводится следующей строкой. Приглашение видеотона `WHAT=` обвязка
пропускает переводом строки. Подробнее — `docs/KAK-IGRAT.md`.

Подсказка в запросе устарела: в ней перечислены только `0` и `1`,
хотя программа принимает и `3`, и `4`.

### Готовая последовательность для ICTRL=3

```
3        TIP — Ту-104
1        MODE — автопилот
3        ICTRL — адаптивный шаг интегрирования
5        NFR — печать кадра каждые 5 секунд
0        IFLIB
2400     TMAX
7351     RSEED
1.5      SIGW — гроза
0.60     DT0 — начальная тяга
STA      пуск непрерывного расчёта
```

Каждая строка вводится в ответ на очередное приглашение `-`;
последняя — в ответ на приглашение приказного цикла.

### Готовая последовательность для ICTRL=4

```
3        TIP — Ту-104
1        MODE — автопилот
4        ICTRL — адаптивный шаг управления
5        NFR
0        IFLIB
2400     TMAX
7351     RSEED
1.5      SIGW
0.60     DT0
DTC      задать шаг управления вручную
0.10     аргумент команды DTC
STA      пуск непрерывного расчёта
```

Строки `DTC` и `0.10` необязательны: без них режим 4 включится с
начальным `DTCTRL=0,1` и будет подстраивать шаг сам. Команду можно
ввести и до запуска, и на паузе. Переход в режим инструктора командой
`INS` для неё не обязателен: в текущем исходнике разбор команд не
проверяет режим, хотя в подсказке `EPS`, `PFL` и `DTC` отнесены к
инструкторским.

## 3. Команды адаптивного шага

Команда — ровно шесть литер латиницей, заглавные; аргумент
запрашивается отдельным приглашением сразу после команды.

| Команда | Аргумент | Что делает | Печать |
|---|---|---|---|
| `EPS` | допуск | задаёт `EPSKM` через `KMSET`; порог ошибки для `KUTMAD` в режиме 3 и порог срабатывания адаптации в режиме 4 | `EPS= ...` |
| `PFL` | порог | задаёт `PFLOOR` через `KMSETP`; порог относительной нормы ошибки в `KUTMAD`, то есть в режиме 3 | `PFL= ...` |
| `DTC` | значение | задаёт `DTCTRL` вручную, с ограничением снизу 0,02 и сверху 0,5 через `DTPAR` | `DTC= ...` |

`DTC` не включает режим 4: он меняет шаг управления внутри уже
включённого режима 3 или 4. Переключает режим только поле ICTRL.

В подсказке `CMDLOOP` и `HLP` перечислена только команда `EPS`. Команды
`PFL` и `DTC` доступны, но намеренно не подсказываются, чтобы не
менять печать приглашений в режимах 0–3. Оператору нужно знать их из
этого отчёта.

## 4. Что печатается в конце

При посадке по высоте (`X[13]<=VHCR`) программа печатает кадр, оценку
и, начиная с режима 2, строку контроля. По лимиту шагов
(`NSTP>=NMAX`) кадра нет, но оценка и строка контроля печатаются так же:

```
OCENKA= 3
KONTROL ERMAX=  0.0001
DTSH=  0.3630        <- только при ICTRL=3
```

В режиме 4 вместо `DTSH=` печатается `DTCTRL=  0.4000`. При `ICTRL=0`
строк `KONTROL ERMAX=`, `DTSH=` и `DTCTRL=` нет.

Если самолёт столкнулся с землёй до выхода на посадочную высоту,
печатается сообщение `STOLKNOVENIE S ZEMLEJ` и `OCENKA=`, но строк
`KONTROL ERMAX=`, `DTSH=` и `DTCTRL=` в этой ветке нет. Это особенность
текущего исходника, а не опечатка в отчёте.

## 5. Команда инструктора ICTL 0/3/4 (реализована)

Реальный рычаг оператора — команда переключения режима без
перезапуска. Предлагаемый вид:

```
ICTL 0     фиксированный шаг, как в регрессии
ICTL 3     адаптивный шаг интегрирования
ICTL 4     адаптивный шаг управления
```

Ветка `ICTL` добавлена в `CMDLOOP` исходника `SRC/GLDIAL.PAS`; она спрашивает число через
`ASK` и `GTINT`, проверить, что оно равно 0, 3 или 4, записать его в
`ICTRL` через аксессор `GLSET(T,DTSH,KTIP,MODE,ICTRL,NFR,IFLIB,TMAX)`
из `/GLOB/`, сбросить `TCTRL:=T` и `DTCTRL:=H`, при необходимости
пересчитать `NPRN` и `NMAX` по текущему `DTSH` и напечатать `ICTL= ...`.
В отличие от команды `PAR`, это не сбрасывает самолёт в исходное
состояние.

Оговорки для реализации: при `ICTRL=3` и `4` во время непрерывного
полёта приказный цикл не вызывается — только на паузе, при пошаговом
режиме `STE` или при `ICTRL=1`. Значит переключаться можно на паузе.
Добавление `ICTL` в текст подсказки `INS:` изменило печать приглашения
и в режиме 0; если это недопустимо, команду можно описать только в
`HLP`. Реализацию делает владелец ядра, в этом отчёте команда только
предлагается.

## 6. Честный GAP

- Автотесты остаются на фиксированном шаге `ICTRL=0`. Проверки 10/10,
  5/5 и совпадение md5 повтора в этой задаче не запускались и не
  перепроверялись; они остаются за владельцем регрессии.
- При `ICTRL=3` печать `DTSH` другая: в конце прогона появляется
  строка `DTSH=`, которой в режиме 0 нет вовсе, а значение шага уже не
  равно 0,1 с. По калибровке шаг доходил до 0,24–0,76 с, то есть
  значение в строке не воспроизводимо побайтово.
- Активность кадров по времени при `ICTRL=3` тоже другая. `NPRN` и
  `NMAX` считаются в `INIT` по шагу 0,1 с: при `NFR=5` кадр
  печатается каждые 50 шагов. Когда `DTSH` вырастает, эти же 50 шагов
  занимают уже 12–38 секунд вместо пяти, а лимит в 24000 шагов
  наступает при времени, намного превышающем `TMAX`. Побайтовая
  сверка с эталоном `ICTRL=0` здесь невозможна в принципе.
- При `ICTRL=4` шаг интегрирования остаётся 0,1 с, поэтому кадры по
  времени совпадают с режимом 0, но печатается `DTCTRL=`, а частота
  пересчёта управления меняется. В грозу это улучшает вертикальную
  скорость по сравнению с режимом 0, но само по себе не доводит
  сценарий до оценки 3 — подробности в
  `docs/analysis/adaptive-control-step.md`.
- Адаптация в режиме 4 использует абсолютную норму ошибки `KUTMER`,
  тогда как `EPSKM` калиброван под относительную норму `KUTMAD`.
  Порог `EPSKM/4` в этом режиме не имеет того же смысла; на практике
  шаг может уйти в нижнюю границу 0,02 с.
- Прогон на эмуляторе не выполнялся: по заданию запрещено запускать
  `install-2348.sh` и сборку. Все выводы о печати получены чтением
  `SRC/GLDIAL.PAS` и существующих отчётов.
- Команда `ICTL 0/3/4` **реализована** в `SRC/GLDIAL.PAS` (ветка в
  `CMDLOOP`, глобал `ICTLV`, обновление подсказок). Проверка в живой игре:
  после `INS`, `ICTL 3`, `STA` прогон завершился с `OCENKA=1` и напечатал
  `DTSH= 4.4533E-01`, то есть шаг интегрирования действительно адаптировался.
  При переключении сбрасываются `TCTRL`, `DTCTRL` и `DTSH:=H`, чтобы не
  оставались значения предыдущего режима. Автотесты по-прежнему подают
  `ICTRL=0` явной картой, поэтому регрессия не изменилась.
