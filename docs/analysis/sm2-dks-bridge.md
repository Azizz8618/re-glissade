# Минимальный мост СМ-2 ↔ «Электроника-60» (этап Q3a)

Дата: 19 ноября 2026 года. Отчёт по задаче «минимальный мост между
эмулируемой СМ-2 и Э-60 для тренажёра „Глиссада-6“».

---

## 1. Какой путь связи возможен без правки C-кода simh

В эталонной связке `/home/azizz/Yandex.Disk/simh` уже работает мост
БЭСМ-6 ↔ Э-60: `besm6_dks.c` — клиент `SET DKS REMOTE=host:port`,
`pdp11_dks.c` — сервер `SET DKS BRIDGE=port`. Кадры D6/D7 идут по TCP.

Между Э-60 и СМ-2 готового моста **нет**: `hp2100_sm2k.c` содержит только
регистр данных `SM2KD`, флаг `SM2KF` и прерывание по вектору, а код выборки
задаётся `SET SM2K SC=n`. Никакого сокета, ни кадров DKS в этом контроллере
нет. Соединить `SM2KD` и TCP-поток DKS внутри simh можно только правкой
C-кода, что в этой задаче запрещено.

Поэтому выбран хост-путь без C-правок:

1. Хост-процесс на Python подключается к TCP-серверу `pdp11_dks.c`
   (порт 4140) и говорит с ним на языке кадров D6/D7 — так же, как это
   делает `besm6_dks.c`.
2. Кадр раскладывается в 16-разрядные слова СМ-2; для контроллера 2К
   генерируются SIMH-команды `DEPOSIT SM2KD`, `DEPOSIT SM2KF`, а слова
   кадра кладутся в память СМ-2 через `DEPOSIT <адрес> <слово>`.
3. Обратный путь — `EXAMINE SM2KD` / чтение буфера слов и сборка кадра
   D6 для отправки в Э-60.

Подача сгенерированных команд в SIMH — отдельный вопрос. Надёжный способ
для работающего симулятора — pty (`pty.fork`), как в приёмочных тестах
ранбука; для статических пакетов достаточно `hp2100 < script.ini`. В прототипе
реализован второй, простой путь; первый остаётся GAP.

## 2. Что реализовано

Файл `TOOLS/sm2_dks_bridge.py`:

| Компонент | Назначение |
|---|---|
| `encode_frame`, `decode_response`, `DksFrame` | Кодирование/разбор кадра `D6 op chan addr_hi addr_lo val_hi val_lo 00` и ответа `D7 op\|0200 …`; строгая проверка маркера, бита ответа, op-кода и диапазонов |
| `DksLink` | TCP-клиент моста; `ping()` (04), `write()` (02), `read()` (01), логирование строк «ОТПРАВЛЕНО / ПОЛУЧЕНО» с hex-байтами |
| `LoopbackDksServer` | Честный хостовый эмулятор **формата кадра и квитирования**, а не модели Э-60: PING/READ/WRITE/ATTN, карта слов, счётчики кадров |
| `Sm2KAdapter` | Кадр ↔ четыре 16-разрядных слова СМ-2, `DEPOSIT`-команды, `DEPOSIT SM2KD` / `SM2KF`, генерация SIMH `.ini`-скрипта |
| CLI | `selftest`, `ping`, `write`, `read`; ключи `--loopback`, `--host`, `--port`, `--sm2-ini`, `--sm2-sc`, `--log` |

Протокольные константы и системные ячейки взяты из ранебука:
`D6`/`D7`, бит `0200` (`0x80`) в ответе, опы 01/02/03/04,
ячейки `0`, `0140`, `0146`, `0154`, `0157`, `077777`; канал КРК 2
(что даёт `002000` в ячейке 0).

Отдельно разведены **номер канала КРК Э-60** (`--chan 2`) и **код выборки
устройства SM2K на шине СМ-2** (`--sm2-sc`, по умолчанию восьмеричное
`020`). Это разные величины: `SET SM2K SC=2` SIMH отклоняет, потому что
коды `0..017` служебные (`HP2100/sm2_params.h`).

Файл `TOOLS/tests/test_sm2_dks_bridge.py`: 13 тестов — точные байты кадров,
отклонение битого ответа, круговое преобразование кадр ↔ слова СМ-2,
проверка DEPOSIT-команд, живой TCP-обмен с эмулятором протокола,
отклонение чужого опкода в ответе, а также выключаемый тест реального
моста (`SM2_DKS_LIVE=1`).

## 3. Как запускать

```sh
cd /home/azizz/Yandex.Disk/re-glissade

# 1. Самопроверка без simh (PING + WRITE + READ + круговое преобразование)
python3 TOOLS/sm2_dks_bridge.py selftest

# 2. Обмен через встроенный эмулятор протокола
python3 TOOLS/sm2_dks_bridge.py --loopback ping
python3 TOOLS/sm2_dks_bridge.py --loopback write --addr 0154 --val 0400 --chan 2

# 3. Живой кадр в pdp11_dks.c (сервер должен быть поднят, порт 4140)
python3 TOOLS/sm2_dks_bridge.py --host 127.0.0.1 --port 4140 ping
python3 TOOLS/sm2_dks_bridge.py --port 4140 write --addr 0154 --val 0400

# 4. Генерация SIMH-скрипта загрузки кадра в СМ-2 и его прогон
python3 TOOLS/sm2_dks_bridge.py --loopback --sm2-ini /tmp/sm2_dks_frame.ini \
    write --addr 0154 --val 0400 --chan 2
/home/azizz/Yandex.Disk/simh/BIN/hp2100 < /tmp/sm2_dks_frame.ini

# 5. Тесты
python3 -m unittest TOOLS.tests.test_sm2_dks_bridge -v

# 6. Тест живого моста (только если pdp11_dks.c слушает 4140)
SM2_DKS_LIVE=1 python3 -m unittest \
    TOOLS.tests.test_sm2_dks_bridge.LiveBridgeTests -v
```

Важно: сервер `pdp11_dks.c` принимает **одного** клиента, и новое
подключение вытесняет предыдущее. Перед пунктом 3 нужно остановить
БЭСМ-6 или выполнить на ней `SET DKS LOCAL`, иначе наш клиент отберёт
соединение у неё (это описано в ранебуке, раздел 6.1).

## 5. GAP, которые остаются

1. **Живая связка СМ-2 ↔ Э-60 не реализована.** Нет кода, который брал бы
   слово из `SM2KD` и отправлял его кадром D6 в `pdp11_dks.c`, а также
   не было бы обратной подачи ответа D7 в `SM2KD`. Для этого нужна правка
   `hp2100_sm2k.c` либо постоянный хостовый процесс с pty-инъекцией
   `DEPOSIT`/`EXAMINE` в работающий SIMH (сложная синхронизация по флагу
   `SM2KF`). Ни то, ни другое в этой задаче не разрешено.
2. **Встроенный сервер — только эмулятор протокола.** `LoopbackDksServer`
   проверяет формат кадра и квитирование, но не воспроизводит прошивку
   СВЯЗЬ7, кольца `0140`/`0146`, системные запросы `0154`/`0157`,
   АБФОСH и ПРП. Он не заменяет `pdp11_dks.c`.
3. **Асинхронный ATTN не обрабатывается.** Клиент читает только ответ
   на свой запрос. Кадр ATTN от Э-60 (оп 03, ПРП канала + ПРП12) может
   прийти между запросами и будет принят за неожиданный ответ; нужен
   отдельный поток приёма с очередью событий.
4. **BULK-опы 05/06 не реализованы.** Поддерживаются только одиночные
   кадры 01/02/03/04, как и требовалось для минимального прототипа.
5. **Ответ WRITE не проверяется по полю val.** Эталонный тест из ранебука
   тоже проверяет только опкод; семантика val в ответе WRITE в исходной
   документации не зафиксирована.
6. **Задачи RCV/SND на СМ-2 не подключены.** Сгенерированный `.ini` —
   каркас загрузки кадра, а не исполняемая задача; приём пакета, CRC и
   двухфазное чтение из плана Q3a остаются за пределами моста.
7. **Кодировка СМ-2 декларативная.** Битовые раскладки `SM2_OP_*`
   не сверены с подлинным железом (GAP плана `PLAN-PERIFERIYA.md`, раздел 3).

## 9. Решение по прямой связке `SM2KD` (19 ноября 2026 года)

Рассмотрен вопрос: патчить ли `../simh/HP2100/hp2100_sm2k.c`, чтобы соединить
регистр `SM2KD` с сокетом моста напрямую. **Решение: пока не патчить,
оставить GAP и работать через хостовый клиент** (вариант B).

Обоснование по прочитанному коду:

- `hp2100_sm2k.c` — пассивное устройство: `UNIT` объявлен как
  `UDATA(NULL, 0, 0)` (нет сервис-процедуры, таймера, сокета, очереди).
  Единственная точка входа — `sm2k_interface()`, вызываемая из
  `io_dispatch()` по I/O-инструкциям. Хуков для внешнего ввода нет.
  Сокетная библиотека `sim_sock.c` при этом линкуется в `hp2100`,
  так что технически патч возможен.
- Сделать `hp2100_sm2k.c` клиентом по образцу `besm6_dks.c` можно
  (~150–250 строк плюс константа в `sm2_params.h`), но есть два
  нерешённых семантических GAP:
  1. не задано отображение «`SM2KD` → конкретная ячейка ОЗУ Э-60»
     (адрес и канал);
  2. `pdp11_dks.c` — одноклиентский (`dks_bsock` один, новое
     подключение вытесняет предыдущее), поэтому второй клиент отобьёт
     соединение у БЭСМ-6.
- Обнаруженный дефект: `sm2k_interface()` выставляет `ioIRQ` без
  `cnVALID`, а `io_dispatch()` обновляет ожидающее прерывание только
  по `cnVALID` (`hp2100_cpu.c:2854–2864`). Аналог в `hp2100_tty.c`
  использует `cnVALID|cnPRL|cnIRQ`. Этот момент требует проверки
  на стенде и также влияет на pty-инъекцию.
- Pty-инъекция SIMH-команд (`Ctrl-E` → `DEPOSIT SM2KD` /
  `DEPOSIT SM2KF` / `EXAMINE`) работает, но `DEPOSIT` не вызывает
  `sm2k_interface()` и не поднимает флаг/прерывание; асинхронный ATTN
  и гонки между `EXAMINE` делают её непригодной как постоянный мост
  для этапов Q5/Q6 с требованием «задержка ≤ одного шага».

Порядок действий: сначала измерить задержку хостового пути; только если
требование «один шаг» не выполняется — делать патч (A) в отдельном
чистом worktree. Рабочий каталог `../simh/master` содержит чужие
незакоммиченные изменения (`BESM6/ACPU/output.txt`,
`BESM6/OSZAGR/dispak.ini`, untracked-файлы); сами `hp2100_sm2k.c`,
`pdp11_dks.c`, `besm6_dks.c`, `sm2_params.h` чисты и идентичны во всех
worktree. Чужие правки не трогать.
