# РЕГИСТРАТОР И ПОВТОР ПРОГОНА ТРЕНАЖЁРА

Дата: 18 ноября 2026 года. Этап 7 плана `docs/PLAN-TRENAZHER-K71.md`.
Контрольная точка — **побайтовое совпадение повторного прогона**.

## 1. Что реализовано

- `SRC/GLRECF.FTN` — регистратор траектории и событий:
  - `/RECF/` — `NR`, `RBUF(18,100)`: `X(13)`, `U(4)`, `T` на каждый кадр;
  - `/RECE/` — `NE`, `IEV(2,40)`: код события и время ввода;
  - **все корректируемые параметры вынесены в отдельный блок `/RECPAR/`**:
    `NFMAX` (лимит кадров), `NEMAX` (лимит событий), `NSTEP` (шаг записи
    в шагах интегрирования). Значения по умолчанию: 100, 40, 50;
  - аксессоры для Pascal: `RCGPAR`, `RCSPAR`, `RECCLR`, `RECPUT`, `RCEVT`,
    `RCN`, `RCGET`, `RCEGET`.
- `SRC/GLDIAL.PAS` — команды инструктора `REC` (начать запись),
  `RPL` (напечатать телеметрию), `RST` (очистить буфер). Запрос
  `RECPUT(X,U,T)` стоит в `DOSTP` с шагом `NSTEP`. События пишутся при
  `INJ` (коды 1–5), `FRZ` (10) и `UNF` (11).
- `TOOLS/replay.py` — запись эталона, повтор и побайтовая сверка потока
  телеметрии. Русские псевдонимы команд: `запись`, `повтор`, `проверка`,
  `список`, `показать`.

Формат кадра телеметрии (фиксированный, пригоден для побайтовой сверки):

```
TELE   1 T= 5.00E+00
  X= 7.6490E+01-4.7850E+00 0.0000E+00 9.99918E-01 0.00000E+00
      0.00000E+00-1.28326E-02 0.00000E+00 0.00000E+00 5.83645E-04
       -1.46E+04  0.000E+00  7.662E+02
  U= 5.50307E-02 0.00000E+00 0.00000E+00 3.88435E-01
EV     1 K=1 T= 0.00E+00
```

## 2. Проверка

| Прогон | Кадров | Событий | md5 потока телеметрии | Результат |
|---|---|---|---|---|
| `record tu104-cal --fault 1` | 47 | 1 | `8d6b07dc50d4d1e90e6da9b8a5f4b3b3` | эталон записан |
| `replay tu104-cal` | 47 | 1 | `8d6b07dc50d4d1e90e6da9b8a5f4b3b3` | **совпадение** |
| `verify` (без отказа) | 40 | 0 | `41a846dde9548f5e9a29e8bf3eb4ca33` (оба прогона) | **совпадение** |

Ответов PASRED: 16/16 с отказом, 15/15 без отказа. Оба прогона завершились
штатно. Регрессия: исторические сценарии **10/10**, упражнения **4/5**
(T2 — ранее зафиксированный GAP).

## 3. Найденные и устранённые проблемы

1. **Зарезервированное слово.** Переменная `RECORD` в Pascal — служебное
   слово; компилятор выдавал `НЕПРАВИЛЬНЫЙ СИМВОЛ` и срывал весь блок
   переменных, из-за чего `GLDIAL` исчезал из PERSO-каталога. Переменная
   переименована в `RECON`.
2. **Передача литерала в `var`-параметр.** `RCEVT(10,T)` давало
   `НЕСООТВЕТСТВИЕ ВИДОВ ПАРАМЕТРОВ ПРИ ВЫЗОВЕ`; введена переменная `IEVK`.
3. **Гомоглиф `Y`/`У`.** Команда `PLY` принималась как `PLУ   ` и не
   распознавалась (`NEPR. KOMANDA`). Команда переименована в `RPL`.
   Это общее правило для словаря команд: латинская `Y` недопустима.
4. **Коррекции пользователя.** Параметры вынесены из тела подпрограмм
   в блок `/RECPAR/`; пользовательский вывод инструментов переведён
   на русский язык. Обе записи — в `docs/corrections.md`.

## 4. Ограничения

- Буфер хранит не более 100 кадров; при `NSTEP=50` это покрывает 500 с
  полёта. При более длинном прогоне младшие кадры теряются (старшие
  перезаписываются только после очистки через `REC`/`RST` — фактически
  запись останавливается на лимите).
- События фиксируют только код и время, без значений органов управления;
  подробности остаются в текстовом логе игры.
- Отказ 1 (потеря тяги) задаётся только в тесте; штатный сценарий повтора
  выполняется без отказа.
