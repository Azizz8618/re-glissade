# Адаптивный шаг управления (ICTRL=4)

Дата: 19 ноября 2026 года.

## 1. Назначение

В режиме `ICTRL=3` адаптируется шаг интегрирования `DTSH`, а шаг
управления `DTCTRL` остаётся жёстко равным 0,1 с. Новый режим
`ICTRL=4` адаптирует именно шаг управления: автопилот и органы
ручного управления пересчитываются чаще или реже в зависимости от
оценки погрешности. Шаг интегрирования в этом режиме фиксирован и
равен `H=0,1 с`: ветка `KUTMAD` выполняется только при `ICTRL=3`.

## 2. Формула адаптации

На каждом шаге `DOSTP` вызывается `KUTMER(X,U,DTSH,ERR)` — оценка
локальной погрешности метода Рунге–Кутты–Мерсона на одном шаге.
Когда наступает момент пересчёта управления (`T>=TCTRL`), управление
пересчитывается, `TCTRL:=T+DTCTRL`, и с этой же оценкой `ERR`
вызывается `DTADJ(ERR,DTCTRL)`:

```
если ERR > EPSKM         : DT := DT * DTDOWN
иначе если ERR < EPSKM/4 : DT := DT * DTUP
иначе                    : DT не меняется
в любом случае           : DT := min(max(DT,DTMIN),DTMAX)
```

Уменьшение шага управления означает более частую выработку
управления, увеличение — более редкую. Новая величина `DTCTRL`
начинает действовать со следующего интервала: `TCTRL` уже вычислен
на прежнем шаге, поэтому есть задержка в один интервал управления.

## 3. Параметры

Все параметры находятся в блоке `/KMCTL/` файла `SRC/GLKMA.FTN`.
Имена не длиннее шести литер.

| Имя | Значение | Смысл |
|---|---|---|
| `DTBASE` | 0,1 | базовый шаг, совпадает с `H` |
| `DTMIN` | 0,02 | нижняя граница шага |
| `DTMAX` | 0,5 | верхняя граница шага |
| `DTDOWN` | 0,8 | множитель при большой ошибке |
| `DTUP` | 1,2 | множитель при малой ошибке |

Подпрограмма `DTPAR(DTB,DTN,DTX,DTD,DTU)` возвращает параметры,
подпрограмма `DTADJ(ERR,DT)` меняет шаг по формуле выше. Блок
`/KMCTL/` расширен до двенадцати элементов во всех шести
подпрограммах, которые его объявляют, поэтому смещения старых семи
полей не изменились.

## 4. Как включить

- В диалоге: ответ `4` на запрос `ICTRL` (карта режима управления;
  в вашей нумерации колоды это четвёртая карта). Остальные параметры
  вводятся как обычно.
- Команды инструктора:
  - `EPS <допуск>` меняет `EPSKM` — порог срабатывания как в режиме
    3, так и в режиме 4;
  - `PFL <порог>` меняет порог относительной нормы (используется
    `KUTMAD`, а значит и оценкой в режиме 3);
  - `DTC <значение>` вручную устанавливает `DTCTRL` с ограничением
    `DTMIN..DTMAX`; границы берутся через `DTPAR`.
- Пакетная программа `GLMAIN.FTN` режим 4 не поддерживает: там шаг
  управления не настраивается.

Собственно переключение режима делается только полем `ICTRL`; команда
`DTC` не включает режим 4, а меняет шаг управления внутри уже
включённого режима 3 или 4.

## 5. Что печатается

В конце прогона при посадке или по лимиту времени при `ICTRL=4`
печатается строка `DTCTRL=` с четырьмя знаками после точки, рядом с
уже существующей `KONTROL ERMAX=`. Строка `DTSH=` по-прежнему
печатается только при `ICTRL=3`. Команда `DTC` сразу печатает
установленное значение в виде `DTC=`.

## 6. Проверка неизменности режимов 0,1,2,3

- Флаг `RECTRL` взводится только при `ICTRL=4`; вызов `DTADJ`
  стоит под условием `if RECTRL`, поэтому для режимов 0–3 он
  никогда не выполняется;
- продвижение времени `T` и повторный `GLSET` внутри ветки
  `ICTRL=4` для режимов 0–3 недостижимы;
- условие `if ICTRL<>3` заменено на `(ICTRL<>3) and (ICTRL<>4)`:
  для 0,1,2 результат прежний, для 3 — прежний;
- строки печати `KONTROL ERMAX=` и `DTSH=` не тронуты, добавлена
  только строка под условием `ICTRL=4`;
- тексты приглашений и подсказок не менялись, чтобы печать режимов
  0–3 осталась прежней;
- старые семь полей `/KMCTL/` остались на первых позициях блока,
  поэтому `KMPAR`, `KUTMAD` и `KMERR` читают те же данные;
- `NMAX` и `NPRN` считаются в `INIT` по неизменному `DTSH=0,1`,
  так что счётчик шагов и частота кадров от `DTCTRL` не зависят.

## 7. GAP и ограничения

- Прогон на эмуляторе не выполнялся: по заданию запрещено запускать
  `install-2348.sh`. Проверена только статическая часть — длины
  строк не превышают 72 символов, колоды успешно сгенерированы
  `TOOLS/build-dialog.py` без запуска эмулятора. Сборка и регрессия
  остаются за вами.
- `KUTMER` из `GLKM.FTN` считает **абсолютную** норму ошибки, а
  `EPSKM` калиброван для **относительной** нормы `KMERR` с порогом
  `PFLOOR`. Порог `EPSKM/4` поэтому не имеет того же смысла, что в
  `KUTMAD`: при больших абсолютных ошибках шаг может уйти в
  `DTMIN` и остаться там. Для практической настройки используйте
  команды `EPS` и `DTC`.
- Коэффициенты 0,8 и 1,2 выбраны эвристически; нет доказательства
  сходимости и сохранения точности при таком управлении. Желательно
  сравнить дебрифинг и `ERMAX` режимов 3 и 4 на одних упражнениях.
- `DTADJ` вызывается только в моменты пересчёта управления; между
  ними шаг не меняется, даже если ошибка выросла.
- Команда `DTC` намеренно не добавлена в текст подсказки `HLP`: это
  сохраняет прежнюю печать режимов 0–3. Команда доступна, но не
  подсказывается в списке.
- Автоматических тестов для режима 4 нет: файлы тестов, `JOB/`,
  диск и калибровки трогать запрещено.
