# Формат нижней части кадра АЦПУ

Документ описывает правку нижних информационных строк кадра в
диалоговой игре «Глиссада-6». Изменён только файл `SRC/GLDIAL.PAS`,
а именно процедура `PRFRM` и две новые вспомогательные процедуры.
Верхняя часть кадра — профиль высоты и вид сверху — не тронута.

Терминал 15ИЭ печатает 80 знаков в ряду. Строки кадра должны
влезать в эту ширину, а строки исходного текста программы,
по принятому в проекте правилу, не длиннее 72 знаков.

## Прежний вид и причина правки

Раньше нижние данные печатались четырьмя строками подряд,
причём Паскаль-Монитор выводил действительные числа через
экспоненциальную запись даже при указании формата `:7:1`:

```
 GLISS 3 GR +----*----+ EGLI=-1.7E+00 M
 KURS LUCH +----*----+ Y= 0.0E+00 M
 SKOR= 7.9E+01 VERT=-4.29E+00 ATAKA= 3.7E+00 TYAG= 1.7E+01
 ZEMLYA= 0.0E+00 PROSVET= 7.6E+02 MIN= 7.6E+02
```

Такая запись плохо читается за штурвалом: вместо `-1.7` и `760.0`
получается `-1.7E+00` и `7.6E+02`. Кроме того, строки не были
выровнены по колонкам.

## Новый макет

Нижние строки разбиты на **два равных столбца по 38 знаков**.
Между ними на позиции 39 стоит разделитель — знак плюс.
Итоговая длина ряда: 38 + 1 + 38 = 77 знаков, что укладывается
в 80 знаков терминала.

- **Левый столбец** — параметры полёта: глиссада, курс, скорость
  и уточняющие величины к скорости.
- **Правый столбец** — данные о рельефе: земля, просвет, минимум
  просвета за прогон.

Раскладка по рядам:

| Ряд | Левый столбец | Правый столбец |
| --- | --- | --- |
| 1 | `GLISS 3 GR`, шкала, `EGLI` | `ZEMLYA` |
| 2 | `KURS LUCH`, шкала, `Y` | `PROSVET` |
| 3 | `SKOR`, `VERT` | `MIN` |
| 4 | `ATAKA`, `TYAG` | пусто |

Подписи и числа стоят на одних и тех же позициях в своих столбцах.
Число занимает поле из 7 знаков, поэтому, например, значения
`EGLI`, `Y`, `SKOR`, `VERT`, `ATAKA`, `TYAG`, `ZEMLYA`, `PROSVET`
и `MIN` всегда заканчиваются на одном и том же столбце.
Недостающие позиции заполняются пробелами процедурой `PAD`.
Машинные токены (`GLISS`, `EGLI`, `KURS`, `Y`, `SKOR`, `VERT`,
`ATAKA`, `TYAG`, `ZEMLYA`, `PROSVET`, `MIN`) сохранены: их
разбирают существующие сценарные скрипты.

Пример нижней части кадра. Вертикальные чёрточки по краям —
линейка в этом документе, в кадре их нет:

```
| GLISS 3 GR +----*----+ EGLI=   -1.7 M+ ZEMLYA=     0.0 M                    |
| KURS LUCH +----*----+ Y=        0.0 M+ PROSVET=  760.0 M                    |
| SKOR=    79.0 VERT=    -4.3          + MIN=      760.0 M                    |
| ATAKA=    3.7 TYAG=   17.0           +                                      |
```

Как и раньше, правый столбец печатается только при включённом
рельефе (`IREL=1`). При `IREL=0` он остаётся пустым, но сохраняет
свою ширину 38 знаков, поэтому разделитель стоит на том же месте.

## Как печатаются числа

Добавлена процедура `PRNUM(R:real; W:integer)`. Она не использует
формат `real:w:d`, который даёт экспоненту, а собирает число из
целых частей:

1. Знак отделяется заранее: если `R<0`, берётся `-1`, иначе `1`.
2. Берётся абсолютная величина, умножается на 10 и округляется
   до десятой доли через `TRUNC(ABS(R)*10.0+0.5)`. Так получается
   целое число десятых долей.
3. Целая часть находится как `N div 10`, дробная — как `N mod 10`.
4. Печать идёт целыми полями: `S*IP:WW`, затем явная точка `.`,
   затем `FP:1`. Параметр `W` задаёт полную ширину поля, `WW=W-2`.

Для используемой ширины `W=7` получаются значения вида `   -1.7`,
`    0.0`, `   79.0`, `  760.0`. Отрицательный ноль не появляется:
если после округления целая часть равна нулю, знак пропадает.
Округление всегда идёт до одного знака после запятой, то есть
до 0,1. Все числа в нижней части кадра печатаются именно этой
процедурой, включая тягу, которая раньше была целым числом.

## Что такое звёздочка

Звёздочка бывает в двух местах кадра, и это разные вещи.

**Звёздочка в правом графе** — маркер самолёта в плане
сверху. В верхней части кадра справа рисуется полоса `+====+`.
Позиция маркера на ней вычисляется как
`IB:=21+TRUNC(X[12]/5.0)` и ограничивается диапазоном от 1 до 41.
Середина полосы, позиция 21, соответствует нулевому отклонению
от оси (`Y=0`), одно деление равно 5 метрам. Чем больше `X[12]`,
тем правее стоит звёздочка. Это и есть ответ на вопрос, откуда
берётся звёздочка в правом графе: она показывает текущее положение
самолёта относительно посадочной оси в плане сверху.

**Звёздочка в нижних строках** внутри `+----*----+` — неподвижная
отметка нуля на шкале отклонения. Сама шкала напечатана как
постоянный текст, её звёздочка не движется. Текущее отклонение
показывается числом рядом: `EGLI` для глиссады и `Y` для курса.

## Как проверять

1. Визуально: подать команду `PRN` или сделать шаг командой `STE`
   и снять кадр. Нижние четыре ряда должны иметь одинаковую длину
   77 знаков и разделитель на одном и том же месте.
2. По длинам рядов и по отсутствию экспоненты — несложная проверка
   по сохранённому тексту кадра:

```python
import re
text = open('frame.txt', encoding='utf-8').read()
for line in text.splitlines():
    if line.startswith((' GLISS', ' KURS', ' SKOR=', ' ATAKA=')):
        print(len(line), repr(line))
        vals = re.findall(
            r'(?:EGLI|Y|SKOR|VERT|ATAKA|TYAG|ZEMLYA|PROSVET|MIN)=\s*([^ ]+)',
            line)
        assert all(re.fullmatch(r'-?\d+\.\d', v) for v in vals)
```

Ожидаемый результат: четыре строки длиной 77 и никаких чисел
с буквой экспоненты. Если рельеф выключен, правые значения
отсутствуют, но длина строк остаётся 77.

3. По исходнику: длины строк программы не должны превышать
   72 знака:

```python
for n, s in enumerate(open('SRC/GLDIAL.PAS', encoding='utf-8'), 1):
    if len(s.rstrip('\n')) > 72:
        print(n, len(s.rstrip('\n')))
```

4. По регрессии: скрипты разбирают числа регулярными выражениями,
   которые допускают и обычную запись, поэтому замена экспоненты
   на натуральные числа не должна менять результат разбора.
