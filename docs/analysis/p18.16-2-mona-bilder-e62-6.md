# п.18.16(2) — Реверс билдера МОНЫ 06200–06245 и семантика Э62 с кодом 6
(А2, сессия 13.11-16)

Продолжение п.18.16(1)/Дополнения 3: что обозначает операция 6, которую
МОНА-80 кладёт в [0o11043] и передаёт супервизору запросом
`Э62 5747(М12)` (00421) после ПУСКа.

## 1. Метод: дамп кэша команд по виртуальным адресам

Дамп физической памяти (core-pc.bin) не содержит МОНЫ на месте её
виртуальных адресов (06070–06260 = нули): код задачи странично
перемещён. Но кэш команд uicore индексируется **виртуальным** pc
(dispak/cu.c: `uicore[pc]`, при супервизорном режиме —
`uicore[pcm]`, где `pcm = pc | 0o100000`). Поэтому:

- `core-uic.bin` = команды задачи по виртуальным адресам;
- супервизорный код лежит в том же дампе по индексам 0o100000+;
- инструмент: TOOLS/disasm_uic.py (формат: reg<<20|op<<12|addr,
  структурные коды 0o100+, эксп-бит в дампе потерян — адреса с
  эксп-битом читаются как addr|0o70000).

Новый прогон: TOOLS/run_k46_core2.py (BESM6_EXIT_ADDR=412 — ПУСК,
BESM6_CORE_ON_PC=00421 — дамп в момент Э62, BESM6_WATCH/RW=1).
Останов «Пока рано» находится в супервизоре (pc=0o1xxxxx), поэтому
дамп по 00422/00423 не срабатывает; 00421 исполняется ровно один раз.
Артефакт: /tmp/k46c421/{core-pc.bin,core-uic.bin,watch.err}.

## 2. Кодировка команд (восстановлена по dispak/defs.h)

Половинка команды 24 бита: М-поле = биты 23–20 (индекс reg[] напрямую,
М16 = 0o16 = reg[14]); бит 19 = «1-я структура» (коды 0o100–0o117:
utc, vtm, uj, v1m...); бит 18 = расширение адреса (addr|0o70000);
биты 17–12 = код операции (0o00=atx, 0o10=xta, 0o15=aox, 0o62=Э62,
0o70=Э70...); биты 11–0 = адрес.

Ключевые семантики из cu.c: `vtm X(r)` = Мr:=X; `utm X(r)` = Мr+=X;
`utc X(r)` = **МОД**: МР:=X+[Мr] и адрес СЛЕДУЮЩЕЙ команды получает
поправку +МР (одноразовый addrmod); `wtc X(r)` = МР:=[X+Мr]+поправка;
`v1m X(r)` = если Мr≠0 → переход на X (cu.c:666, opcode 0115).

## 3. Точка Э62: 00421

```
00411 Э74 0000(0)          останов КОНЕЦ ЗАДАЧИ (*74)
00412–00420                восстановительный блок (М1–М15 из 00412-обл.)
00421L Э62 5747(М12)       операнд = 5747+[М12=0o3074] = 0o11043
00421R vtm 5500(М12)       (после возврата М12 := 0o5500)
00422+                     НЕ ИСПОЛНЯЛОСЬ: останов в супервизоре
```
М1–М15 при Э62 (восстановительный блок, п.18.16(1)): М5=0o1121,
М12=0o3074, М14=0o11043, М15=0o75402; МР (М-регистр поправки)=0o10002
(виден в WATCH при исполнении билдера 06207). Протокол Э62:
М16 := [операнд] = [11043] = **6**.

## 4. Билдер 06200–06245 (uicore, k46-core411 + k46c421)

```
06200 sti 0(0)    | vtm 0015(М16)
06201 utm -1(М16) | sti 1(М16)
06202 v1m 6201(М16) | utc 6334(0)
06204 vtm 0002(М5)| xta 3775(М5)
06205 aex 0275(М7)| uza 6242(0)
06206 vtm 3774(М16)| utc 0(0)        ← МОД 0(М0)
06207 utc 0(М5)   | xta -1(М16)      ← МОД 0(М5): МР:=М5=0o10002
06210 utc 0(М5)   | atx 1(М16)       ← [М16+1+МР] := АСС
06211 utm -1(М16) | v1m 6207(М16)   ← М16-- , цикл пока М16≠0
06212 xta 0335(М7)| atx 0(М5)
...
06231 xta 2(М1)   | atx 0(М1)        ← [М1+0] := [М1+2]
06232 xta 3(М1)   | atx 1(М1)        ← [М1+1] := [М1+3]  ← ФИНАЛ: [11043]:=6
06233 aex 0275(М7)| uza 6235(0)
06234 utm 2(М1)   | uj 6231(0)       ← М1 += 2, цикл
06235 atx 3(М1)   | uj 6222(0)
```
(atx/xta с адресами −1 = 0o7777/0o77774 — эксп-адреса.)

СЛЕДОВАТЕЛЬНО: 06207–06211 — цикл сдвига вверх на 2 слова:
`[0o10003+М16] := [0o10001+М16]` по убывающему М16 (при М16=0o1040
это [11043] := [11041] — значения в WATCH 7210620001700000, 6, 4 —
последовательные содержимые [11041] в течение задачи);
06231–06235 — цикл «сжатия окна»: `[М1] := [М1+2]; [М1+1] := [М1+3]`
с шагом М1 += 2 (06232R при М1=0o11042: [11043] := [11045]). Это
**сборка/перемещение элементов таблицы операций МОНЫ** (зона
0o11000–0o11060), а не одноразовый билдер запроса.

## 6. Путь отказа: супервизор и «Пока рано»

В uicore прогона с ПУСКом исполнен выход супервизора:
```
100010 ntr 7(0) | uj 3651(0)   «нереал»: немедленный переход в задачу
```
Вход 100011 (errchk) обслуживает Э62 по таблице диспетчера; кода 6 в
ней нет (rukava.be: 0000=КОНЕЦ ЗАДАЧИ, 0010=продолжение перехваченного
экстракода, 0040–0130=терминалы/потоки/подчинённые) → «нереал» →
03651 (обработчик нереал ДУБНЫ/МОНЫ) → rte-77 (03663) → печать
«Пока рано» с дампом СМ (pc=00422, R=000110) → Э74 → eexit() →
JMP 412 (BESM6_EXIT_ADDR) → повтор. Мини-e62() знает только коды
0, 42, 44, 53, 55, 57, 76 и 41 (вых.поток).

## 7. Ответ на вопрос п.18.16(2): что такое операция 6

1. **6 — код операции МОНЫ-80 в её собственной таблице операций
   (зона 11000–11060)**, а не документированный код Э62 ДИСПАК.
   Протокол Э62 при этом стандартный: операнд = адрес ячейки с кодом
   ([11043]), М16 := код, супервизор диспетчирует по нему.
2. Строка операции 6 содержит, кроме ФИО-слова, **исполнимые слова
   `xta 6200(М16) | Э70 6200(М1)`** — подготовленную команду обмена
   с барабаном (Э70). Спул печати задачи лежит на барабане u=20
   (п.18.15(2), 18.16(1)).
3. Запрос делается ОДИН раз, в финале задачи (после КОНЕЦ ЗАДАЧИ,
   по ПУСКу), и по смыслу совпадает с гипотезой (b) п.18.16(1):
   **6 = запрос выдачи (печати) выходного потока задачи**, для
   которого в штатном ДИСПАКе служит Э62 41 (ekdisp э6241: чтение
   зон потока с диска по паспорту задачи + ТБУФ «40-го листа»).
   Отказ «нереал» → «Пока рано» — машина стоит, печать не идёт.

## 8. Следствие для п.18.16(3)

Если 6 = выдача, то реализация Э62 6 в e62() (dispak/cu.c) должна
повторить механизм э6241 из ekdisp: по паспорту задачи взять номер
зоны выходного потока, читать зоны с барабана (вчоб/физур → Э70),
выдавать «40-й лист» через ТБУФ, «такой зоны пока нет» = конец.
Ожидаемый результат: печать файла печати (IA/B/READ OK, u=20
тракт 5) на АЦПУ после ПУСКа.
