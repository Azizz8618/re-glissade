# п.18.21 — Контракт маркеров подтверждён арифметикой; ИСПОРЧЕН устранён полностью
(А2, сессия 14.11.26-2, продолжение п.18.20)

## 1. Коррекция п.18.20(г): эталоны классификатора = k12-маркеры

В п.18.20(г) эталоны 10633 были прочитаны как [11176]/[11177] — это
ошибка восьмеричной арифметики: `aex 6(2)` при М2=11172 читает
**[М2+6] = [11172+6] = [11200]**, `aex 7(2)` — **[11201]**. Доказательства:

- mtr18-хвост: старьё 0o4024160122640520 ^ [11200](0o3000000000000000)
  = 0o7024160122640520 — точно совпадает с MTR-печатью (digit 4^3=7,
  остальные разряды без изменений);
- вызов (1): [76012] = [11201] → XOR-7 = 0 → тип И14=0 (atx AU=0),
  что сходится с MTR при статичных эталонах;
- схема классификатора: `xta 76000(4)` (М4: 0o12→0o44, шаг 0o32);
  XOR [11200] → И14=3 (конец листа); XOR [11201] → И14=0 (продолжение);
  иначе И14=1 (сбой).

**Walker 10633 ждёт ровно те же k12-маркеры [11200]/[11201] на
границах 0o12+0o32k** — контракт mk_seed_k12. Дамп-значения
[11176]/[11177] (0o2400000000000000/0o1000000000000000) — соседние
слова таблицы, не эталоны.

## 2. Баг v10 и фикс v13

В v10 после записи маркера на границу `bnd` указатель `pos` не
сдвигался — следующая карта начиналась с bnd и **затирала маркер**.
Поэтому все раскладки v9–v12 давали death на 0o44: в буфере маркеров
фактически не было.

**v13** (dispak): маркер на 0o12+0o32k, карта (12 слов ISO + EOR) +
филлер между маркерами, `pos = bnd + 1` после маркера, [11200] на
последней границе. Результат (native24/25/30):

```
RЕСОRDП    3    1    0    5    1     ×6   ← форматное чтение идёт
I/O-ERROR 201 ... FORMAT             ×6   ← 201-петля
КОНЕЦ ЗАДАЧИ (штатно)
ИСПОРЧЕН: 0    ← впервые! death-механика полностью снята
```

## 3. kcount-реарм [0417]: ловушка pc = 01004

- abpc в cu.c = pc исполняемой полукоманды; конвейер входит на
  **01004** (pc 01000 не исполняется);
- отладочная печать `KCNT: on_pc=...` добавлена в cu.c;
- патч срабатывает (`EXECUTE [0417] := 00414 at pc 01004 (each
  entry)`), но 201-петлю не снимает: ротация МОНЫ (pc 77161: чтение
  [0417]=0o35; 06211: чтение карта-слова) перезаписывает [0417], а
  контроль 01523-01526, видимо, требует штатной установки A+L
  ротацией (стадия 0417 РЛС-ротации, п.15.5), а не константы 414.

## 4. 201-петля — оставшийся барьер

6 повторов карты 1 (`RЕСОRDП 3 1 0 5 1` + `201 ... CALLED FROM
01005B/01007B ... FORMAT`), затем штатный конец задачи без счёта/WRITE.
Это тот же барьер, что в 18.18-эре native3/4, где «задача дошла до
счёта: 201-петля на картах, затем WRITE(6)» — но там после петель
счёт шёл (конверт v1: header МОНА-RLE verbatim, карты с 0o1144), а в
v7-конвейере задача закрывается после 6 повторов.

Гипотеза для п.18.22: стадия 41 («проверка на код 012», п.15.6)
ожидает EOR-слово на **конце** 0o32-записи (как в h-сиде: EOR@0o45,
0o62), а не внутри карты (v13: EOR@0o30).
