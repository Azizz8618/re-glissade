# п.18.20 — Натуральный путь доведён до рубежа POINT 00044 (форматный READ работает)
(А2, сессия 14.11-26, продолжение п.18.19)

Цель п.18.20(1): «полный MTR-лог всех вызовов 10633 (успешные vs death) +
сверка с 14.8-эрой, где h-сид проходил IOXXFMR до POINT 00044».

## 1. Регрессия s6h-пути: причина найдена и снята

Современный бинарь на TEST-READ + seed-h умирал «ИСПОРЧЕН РЕКОРД
POINT 00012», тогда как в 13.11-13 (repro-s6h) h-сид доходил до
«I/O-ERROR 201 ... FORMAT». Контрольный эксперимент (era-бинарь из
коммита 01d817b, собран через git worktree) воспроизвёл 201-FORMAT —
регрессия подтверждена. Причина: run_k1_core.py передаёт
BESM6_LUN45_EXECUTE=414; патч (п.14.8-3/18.18) перезаписывает ШТАТНУЮ
установку [0417] при первом redirect. Без переменной современный
бинарь проходит s6h-путь штатно. Вывод: EXECUTE-патч — только для
GLIS1R.

## 2. v7 — перенаправление УИК-проверки на конверт-тракт

MTR-лог (g1r-mtr18) показал: классификация 10633 идёт МЕЖДУ УИК-
проверкой (12205) и первым fetch'ем (00052), а буфер УИК-проверки =
**76000** (SHEET-лог с адресом буфера: `buf=76000`). До v7 УИК-
проверка (u=45 → LUN45-redirect → 20/04) грузила в 76000 сырую RLE-
зону → [76012] = старьё 0o4024160122640520 → класс 10633 тип 1 →
статус 0o21 → ИСПОРЧЕН POINT 00012. В s6h-эре сид лежал на тракте 04,
и УИК-проверка грузила в 76000 КОНВЕРТ штатно.

**v7** (dispak/extra.c, арминг-ветка): сам Э70 УИК-проверки
перенаправляется на конверт-тракт (BESM6_NTV_TRACT, умолч. 06).
Результат (g1r-native20):

```
I/O-ERROR 201 ... LUN 05 ADDRESS 03065B FORMAT   (x4)
(5I5)
RЕСОRDП  3  1  0  5  1                            <- карта 1 прочитана форматным READ(5)!
ИСПОРЧЕН РЕКОРД ... POINT 00044
```

ИСПОРЧЕН POINT 00012 исчез; смерть сместилась на **POINT 00044** —
закономерный рубеж 14.8-эры (п.15.4: идентичная картина «201 +
ИСПОРЧЕН 00044 + RЕСОRDП 3 1 0 5 1 - карта доходит верной»). Впервые
с 18.11-эры задача получает данные.

## 3. Классификатор 10633 — полная схема

```
10633 wtc 0043 | xta 76000(4)   acc := [76000+М4]; М4: 0o12 -> 0o44 (шаг 0o32)
10634 aex 6(2)  | vtm 3(16)     acc ^= [М2+6]; И14 := 3
10635 uza 10640                 ==0 -> 10640 (тип 3)
10635 aex 6(2)                  восстановление
10636 aex 7(2)  | vtm 0(16)     acc ^= [М2+7]; И14 := 0
10637 uza 10640                 ==0 -> 10640 (тип 0)
10637 vtm 1(16)                 И14 := 1 (тип 1)
10640 ita 16(0) | atx 3(1)      acc := И14; [М1+3] := тип ([75443])
10641 uj  0(6)                  возврат
```

- Эталоны СТАТИЧНЫ: [11176] = 0o2400000000000000 = 2^46+2^44,
  [11177] = 0o1000000000000000 = 2^42 (дампы 1-го и 2-го вызовов
  идентичны). Внимание: dump_cells печатает %016o с ведущими нулями —
  int('0240...',8) в Python отсекает их; октальная запись слова =
  16 цифр.
- conv-гипотеза снята: CV-дамп (cu.c) показывает нулевую конволюцию
  ядра во всех буферах.
- Писатели [76012] (WATCH): только лексикон 06134 (2 записи) —
  никаких программных перезаписей; единственный перезаписывающий
  фактор — Э70 УИК-проверки (устранён v7).

## 4. Перебор раскладок записей (v8–v12) — все дают death на 00044

| версия | раскладка | death |
|---|---|---|
| v8/h-точная | записи 13 слов (12 ISO+EOR) подряд, [11200] после | 00044 |
| v9 AC-маркер | 0o1<<42 на границах 0o12+0o32k (п.15.6 «AC '1' в 48 р.»); вызов (2) дал тип 0 на маркере | 00044 |
| v10 | [11201]/[11200]-границы (mk_seed_k12) | 00044 |
| v12 | эталон-слова (0o2400…/0o1000…) на границах | 00044 |

Death стабилен: walker М4=0o44, [75444]=0o45, [75446]=0o44 (POINT
печати), [75443]=0o21. Эталоны-маски при death-вызове не совпадают ни
с [11200]/[11201], ни с AC, ни с эталон-словами — ротационный механизм
(Э75 76424 через [11176-11177], связка с [0414-0417] характеристикой
строки, п.15.2-15.3) формирует их динамически из FORMAT-разбора (5I5).

## 5. Позиция в цепочке

Рубеж «POINT 00044» — это ОТКРЫТЫЙ контракт записи IOXXFMR (п.15.6,
ioxxfmr%.asm: «AC '1' в 48 р. = выход на новый рекорд; 40=обмен;
41=проверка на код 012; 42=закрытие рекорда») — он был открыт и в
14.8-эре, после чего серия ушла в обход через сиды k12/TSTREAD.
Натуральный путь (v7) теперь стоит на том же рубеже, но уже с
прочитанной картой 1 и полным лексиконом 6 модулей. Осталось
реверсировать ротационную связку эталонов — последний шаг READ.
