# Справка оператора-пилота в текстовом диалоге «Глиссады-6»

Дата: 19 ноября 2026 года.

## 1. Что сделано

Короткие списки команд в ветке `HLP` приказного цикла `CMDLOOP`
(`SRC/GLDIAL.PAS`) заменены на вызов новой процедуры `HELP(P:integer)`.
Процедура печатает одну из трёх страниц справки. Само имя команды `HLP`
не изменилось: скрипты `TOOLS/pilot_queue.py` по-прежнему распознают
её кодом 41.

### Как вызывать

| Ввод | Что печатается |
|---|---|
| `HLP` | страница 1, как и раньше, без дополнительного приглашения |
| `HLP 1` | страница 1 — пилот |
| `HLP 2` | страница 2 — инструктор |
| `HLP 3` | страница 3 — полётное задание |

Номер страницы разбирается прямо из введённой строки: команда занимает
позиции 1–3, пробел — позицию 4, цифра 1–3 — позицию 5. Отдельного
приглашения после `HLP` нет. Если цифры нет или она не из диапазона
1–3, открывается первая страница. Глобал `HPAGE` обнуляется при каждом
вызове `CMDLOOP`, поэтому обычный `HLP` всегда возвращает первую
страницу, даже после `HLP 2` или `HLP 3`.

Выбор страницы не зависит от режима `PIL` или `INS`: справка доступна
в обоих режимах. Подсказка о вызове добавлена в меню `CMDLOOP`:
`HLP 1/2/3 - СПРАВКА ПИЛОТ/ИНСТРУКТОР/ЗАДАНИЕ`.

## 2. Страница 1 — пилот: управление

Все команды управления, их аргументы, шаг, пределы и единицы измерения.

| Команда | Орган | Параметр | Шаг | Предел |
|---|---|---|---|---|
| `EV+` / `EV-` | руль высоты | `DE` | 0.05 | −0.30…+0.30 |
| `AI+` / `AI-` | элероны | `DA` | 0.05 | −0.15…+0.15 |
| `RU+` / `RU-` | руль направления | `DR` | 0.05 | −0.20…+0.20 |
| `TH+` / `TH-` | тяга | `DTZ` | 0.05 | 0.00…1.00 |

Абсолютные команды задают значение сразу: `DE=Z`, `DA=Z`, `DR=Z`,
`TH=Z`; число `Z` пишется после знака равенства и проверяется по тем же
пределам. `DE`, `DA`, `DR` — доли отклонения руля, безразмерные; `DTZ` —
доля тяги, значение 1.00 соответствует полной тяге. Шаг команды `STE`
равен `H = 0.1` секунды.

Остальные команды пилота: `STA` (пуск), `STE` (один шаг), `STO`
(останов), `PAR` (запрос параметров и перезапуск), `PRN` (печать кадра),
`AUTO` (автопилот, рули в нуль), `TRIM` (рули в нуль, тяга сохранена),
`NEUT` (всё в нуль и автопилот), `INS` (режим инструктора), `EXIT`.

### Каденция запроса к пилоту

Команда `PILOT 0..100`: `0` выключает запросы, числа 1–100 задают число
шагов модели между ними. На запрос программа печатает кадр, встаёт в
паузу и ждёт команду пилота. После введённой команды полёт продолжается;
исключения — `STO`, `EXIT`, `FRZ`, `PILOT`, после которых пауза
сохраняется. Каденция не связана ни с печатью кадров по `NFR`, ни с
режимом `ICTRL`.

## 3. Страница 2 — инструктор: команды и значения

| Команда | Аргумент | Назначение |
|---|---|---|
| `SEL` | 1…5 | выбрать упражнение T1…T5 |
| `FRZ` / `UNF` | — | заморозка и снятие заморозки модели |
| `INJ` | 1…5 | ввести отказ |
| `EPS` | > 0 | допуск ошибки, порог адаптации в режимах 3 и 4 |
| `PFL` | > 0 | порог относительной нормы ошибки в режиме 3 |
| `DTC` | 0.02…0.50 | шаг управления вручную (`DTMIN…DTMAX`) |
| `FUL` | ≥ 0, кг | дополнительное топливо |
| `RES` | > 0 | множитель резерва топлива |
| `FLP` | 0/1/2 | закрылки: убраны / взлётные / посадочные |
| `GER` | 0/1 | шасси: убрано / выпущено |
| `SPL` | 0/1 | спойлеры: убраны / выпущены |
| `ICTL` | 0/3/4 | шаг: фиксированный / интегрирования / управления |
| `REC` / `RPL` / `RST` | — | запись, воспроизведение, очистка записи |
| `SCR` | — | дебрифинг задания |
| `PIL` | — | вернуться в режим пилота |
| `HLP` | 1/2/3 | эта справка |
| `EXIT` | — | выход |

`EPS` задаёт `EPSKM` через `KMSET`, `PFL` — порог `PFLOOR` через
`KMSETP`, `DTC` — `DTCTRL` с ограничением через `DTPAR`. Команда `DTC`
не включает режим 4: она меняет шаг управления внутри уже включённого
режима 3 или 4; переключает режим только `ICTL` (поле `ICTRL` карты или
команда). `FUL` и `RES` меняют запас топлива через `FUELSE`.

## 4. Страница 3 — полётное задание

Страница печатает текущие параметры полёта и определяет, какое из
упражнений T1…T5 загружено.

### Текущие параметры

| Величина | Что печатается |
|---|---|
| `KTIP` | номер типа и название самолёта |
| `MODE` | 1 — автопилот, 2 — программный полёт |
| `ICTRL` | 0/1/2/3/4 — режим шага и управления |
| `SIGW` | интенсивность турбулентности |
| `RSEED` | начальное значение датчика случайных чисел |
| `DT0` | начальная тяга |
| `TMAX` | лимит времени, секунды |

Соответствие `KTIP` названиям: 1 — МиГ-15, 2 — Ил-28, 3 — Ту-104,
4 — Ан-24, 5 — Ан-2. Для неизвестного номера печатается
`САМОЛЁТ: НЕИЗВЕСТНЫЙ ТИП`.

### Как задание определяется по EX-массивам

В начале программы глобалы `EXKTIP`, `EXSIGW`, `EXRSEED`, `EXDT0`,
`EXTMAX` заполнены эталонными наборами для T1…T5. Команда `SEL n`
копирует набор `n` в рабочие `KTIP`, `SIGW`, `RSEED`, `DT0`, `TMAX`.
Справка перебирает `n` от 1 до 5 и считает задание определённым, если
все пять полей совпали: `KTIP` — точно, вещественные — с допуском
0.0001. Найденный номер печатается как `ЗАДАНИЕ Tn ОПРЕДЕЛЕНО ПО
EX-МАССИВАМ`; если ни один набор не подошёл — `ЗАДАНИЕ T1..T5 НЕ
ОПРЕДЕЛЕНО` (например, параметры введены вручную командой `PAR`).

| Задание | KTIP | SIGW | RSEED | DT0 | TMAX | Название |
|---|---|---|---|---|---|---|
| T1 | 3 | 0.0 | 7351.0 | 0.60 | 2400 | Ту-104: штиль, точная посадка |
| T2 | 1 | 1.5 | 7351.5 | 0.60 | 2400 | МиГ-15: гроза у аэродрома |
| T3 | 2 | 0.5 | 7351.5 | 0.60 | 2400 | Ил-28: сложные метеоусловия |
| T4 | 4 | 0.0 | 7351.5 | 0.60 | 2400 | Ан-24: заход в тумане |
| T5 | 5 | 0.3 | 7351.5 | 0.60 | 2400 | Ан-2: умеренная турбулентность |

### Цель посадки и сценарий

Цель печатается одной строкой: `VERT<=4.0`, `TCH>=0`, `OCENKA<=3`.
Короткое описание сценария выбирается по номеру задания: год, место,
условие.

| Задание | Короткая строка в справке |
|---|---|
| T1 | ТУ-104 ШТИЛЬ, ТОЧНАЯ ПОСАДКА |
| T2 | МИГ-15 1952 ГРОЗА У АЭРОДРОМА |
| T3 | ИЛ-28 1958 СЛОЖНЫЕ МЕТЕОУСЛОВИЯ |
| T4 | АН-24 2010 ТУМАН, ИГАРКА |
| T5 | АН-2 УМЕРЕННАЯ ТУРБУЛЕНТНОСТЬ |

## 5. Машинные токены

Процедура `HELP` не печатает служебные токены `EGLI=`, `VERT=` и
`OCENKA=`, которые разбирают скрипты `TOOLS/exercises.py`,
`TOOLS/calib/scenarios.py`, `TOOLS/calib/verify_all.py` и
`TOOLS/install-2348.sh`. Строка цели использует знак `<=`: в ней нет
подстрок `VERT=` и `OCENKA=`, поэтому регулярные выражения
`VERT=\s*...` и `OCENKA=\s*...` справку не захватят. Печать кадра
(`PRFRM`) и выдача оценки в конце прогона изменены не были.

## 6. Честный GAP

- Описания сценариев — короткие строки, захардкоженные в `HELP` по
  номеру задания. Целого json-сценария в игре нет: файлы
  `TOOLS/exercises/T1.json` … `T5.json` — внешние данные для скриптов,
  диалог их не читает. Год и место взяты из поля `source` этих файлов.
- Подсказка в `CMDLOOP` добавлена в обе ветки меню; это меняет печать
  приглашения, но не разбор команд. Номер страницы считывается только
  с позиции 5; ввод вида `HLP12` или `HLP 10` трактуется как первая
  страница.
- Условие совпадения с EX-массивами использует допуск 0.0001 для
  вещественных полей: задание, введённое вручную теми же числами, будет
  распознано как Tn.
- Сборка, `install-2348.sh` и регрессия не запускались: по заданию это
  остаётся за владельцем сборки. Изменён только `SRC/GLDIAL.PAS` и этот
  отчёт; ядро Фортрана, `JOB/`, диск, `TOOLS/`, `docs/PLAN-*` и
  `README.md` не тронуты.
- Длины всех строк исходника не превышают 72 символов, новые имена —
  не длиннее шести литер.
