# ТЕХНИЧЕСКОЕ ОПИСАНИЕ ПРОБЛЕМЫ: PERSO-БИБЛИОТЕКА И Э62 В ДИСПАК

Документ описывает механизм загрузки подпрограмм из личной библиотеки
(PERSO) в Мониторе-80, причину, по которой вызовы `ATM`/`NR` из игры не
работают в эмулятореДиспак, и точное место возникновения ошибки.

Дата: 17 ноября 2026 года. Источники: исходники `monitor80-re`, `re-dispak`,
`dispак`, аналитические записки re-glissade, трассы и дампы в
`/tmp/.private/azizz/opencode/phase3/`.

> **Уточнение диагноза (итог расследования).** Первоначально причиной падения
> считалась ошибкаДиспак в обработке Э62. Проверка по книге Тюрина и
> практические прогоны это опровергли: обработка Э62 вДиспак соответствует
> книге, а настоящий барьер — отсутствие линковки внешних символов PERSO
> (подмены каталожного слова переходом к телу модуля). Разделы 4.4–8 отражают
> исправленный диагноз; разделы 1–4.3 описывают наблюдавшиеся симптомы и остаются
> полезны как фактический материал.

---

## 1. Постановка задачи

Программа «Глиссада-6» в варианте `GLNUM.FTN` вызывает две подпрограммы
стандартной библиотеки:

```
CALL ATM(HG,TK,RHO)   — стандартная атмосфера, каталожный номер АЗ01
CALL NR(RN)           — нормальная случайная величина, каталожный номер АВ07
```

Имена `ATM` и `NR` найдены в каталоге тома 2248 (зона 0470(8)); каталог
скопирован в зону 3000(8) тома 2348. Загрузчик ФОРЭКС при сборке программы
печатает:

```
FС*722   Е 02133   ОТСУТСТВУЕТ  NR
IОЕND*   Е 02140   ОТСУТСТВУЕТ  АТМ
```

затем задача завершается аварийно. Ниже — почему.

## 2. Как устроена загрузка библиотек в Мониторе-80

### 2.1 Два разных типа библиотек

В системе сосуществуют два независимых механизма:

| Тип | Карта | Источник каталога | Ссылки в объекте |
|---|---|---|---|
| **PERMANENT LIBRARY** (постоянная, ОБСП) | `*LIBRARY:i`, `i ≤ 24` | список `LTAPES` (ячейка 73B) на системном томе | `C=0o6300` |
| **PERSONAL LIBRARY** (личная, PERSO) | `*personal library:<dev><zone>` / `*perso:<dev><zone>` | зона на подключённом томе | `C=0o6700` |

Обе карты `*LIBRARY:i` и `*ASSIGN-LIBRARY-i` — одна и та же по Мазному
(§1.2.3, 1.2.14). Разделитель `:` — плавающий формат, `-` — фиксированный.

### 2.2 Ветвление по номеру в `loadlibr.asm`

`monitor80-re/utility/loadlibr.asm`:

```
:29    LTAPES: ,EQU,73B       ; список LIBRARY
:200   ,XTA,NLIB
:201   ,A-X,C30              ; C30 = 0o30 (LOG,30 при :879)
:202   ,U1A,ОБСП             ; NLIB > 24 → ветка ОБСП
:203   ,XTA,NLIB
:204   ,ASN,64-12
:205   ,ATX,IRI              ; системная библиотека → чтение LTAPES
:207   ОБСП: ,WTC,NLIB
:208   ,XTA,3750B
:209   ,U1A,havelib
:214   havelib: ,VTM,LENT*
:216   ,CALL,ДАЙЛЕНТУ        ; чтение каталога с устройства
```

То есть при `i ≤ 24` каталог берётся из `LTAPES` **системного тома**, и карты
`ЛЕН 42(2248)`/`ЛЕН 41(2348)` на этот список не влияют. Поэтому пробы
`*library 1/2/7/10` давали «ОТСУТСТВУЕТ». При `i > 24` (`30B..67B`) номер
трактуется как математический номер объявленного МД/МЛ, и каталог читается с
устройства через `ДАЙЛЕНТУ`.

### 2.3 Permanent-зависимости ATM и NR

По таблицам символов самих объектных модулей (совпадает с
`dispак/tests/librefer-2248/output.txt`):

```
ATM: A/MINUS, A/NOT, EXP*, LN*, SQRT*, A/PROCRT   — все C=0o6300
NR:  A/I0, A/SIGN, ENTIER*, SQRT*, A/PROCRT       — все C=0o6300
```

Все этиPermanent-входы находятся на системном томе 2048 в зоне 0200
(подтверждено `besmtool search 2048`): ` А/РRОСRТ`, ` А/SIGN`, `ЕNТIЕR*`,
`SQRТ*`, `LN*`. То есть для зависимостей PERSO-образ не нужен — их должна
обеспечить постоянная библиотека монитора. Системный том 2048 обязан
оставаться подключённым, что и зафиксировано в шапке колоды `лен 41(2048)^`.

### 2.4 Формат записи каталога PERSO

Образ `/tmp/full2248lib.bin` (40 зон, каталог 2248 зоны 0470, 332 записи).
Каждая запись — два 48-битных слова:

```
слово 0: имя, 8 символов кодировки TEXT
слово 1: (дата << 24) | (длина_загрузки × 8 << 12) | оверлей
```

Примеры:

| Имя | Слово записи | Старшие 24 бита (дата) | Длина | Оверлей |
|---|---|---|---|---|
| ATM | `0o3210520031300000` | `0o32105200` | `0o3130/8 = 203` слова | 0 |
| NR  | `0o3650710011400000` | `0o36507100` | `0o1140/8 = 76` слов | 0 |

Тела модулей находятся сканированием по 32-словным границам и полю `head`
(см. `re-siprod/tools/siprod_lib.py:89-119`) — **адреса в записи каталога нет**:

```
ATM: смещение 10880 слов (0o25200), байт 65280
     head=1, sym=6, long=4, cmd=129, const=74
NR:  смещение 26528 слов (0o63700), байт 159168
     head=1, sym=5, long=4, cmd=56, const=20
```

Номер входа личной библиотеки равен **позиции записи в каталоге**. Поэтому
нельзя удалять/уплотнять записи — ломаются 11 ссылок `C=0o6700` в других
модулях. Допустимо только обнуление слова записи на месте с сохранением слова
имени и завершателя каталога.

## 3. Каталожная заглушка — ключевой механизм

### 3.1 Что находится в начале образа библиотеки

Первые слова образа `/tmp/full2248lib.bin`, дизассемблированные как команды:

```
00000  atx   0000(0) | wtc   12240(0)
00001  atx   0000(0) | atx   0000(0)
00002  vtm   46364(14) | Э62  70000(10)
00003  aax   74500(4) | stop  0000(1)
00004  Э56   76354(12) | ita   70000(12)
00005  *21   14401(5) | ati   70000(4)
```

Дизассемблированная «команда» `Э62 70000(10)` — это **информационное слово
записи каталога** (дата/длина), проинтерпретированное как машинная команда.
При переносе каталога из зоны 0470 в зону 3000(8) смещение операнда изменилось
с 70000 на 74400: разница `74400 − 70000 = 4400(8)`.

### 3.2 Как заглушка оказывается в памяти задачи

При сборке FОRТRАN-программы загрузчик берёт слово записи каталога как точку
входа (transfer vector) для внешней подпрограммы и помещает его в память
задачи. Там оно начинает исполняться как настоящий экстракод Э62. В прогоне с
PERSO-библиотекой по адресу 71010 зафиксировано:

```
[71010] = 0o6245664341624400
        → vtm 56643(М14) | Э62 74400(М10)
M10 = 14625(8)
```

## 4. Трап Э62 вДиспак (наблюдаемый симптом)

### 4.1 Установка регистра 16

`dispак/cu.c:787,797` при обработке трапа экстракода:

```c
reg[TRAPRETREG] = nextpc;
JMP(nextpc);
reg[016] = ADDR(addr + reg[ui.i_reg]);
reg[TRAPNREG] = ui.i_opcode - 050;
```

`ADDR(x) = (ushort)(x) & 077777` из `defs.h:257`. Для нашего случая:

```
reg16 = ADDR(74400 + 14625) = ADDR(0111225) = 011225(8)
```

### 4.2 Обработка в e62()

`dispак/extra.c:1768-1833`:

```c
e62(void) {
    switch (reg[016]) {
    case 0:      /* unconditional termination */
    case 0042:   /* flush output */
    case 0044:   /* cancel output */
    case 0053:   /* set intercept mask */
    case 0055:   /* get error catcher */
    case 0057:   /* acquire terminal */
    case 0076:   /* drop incognito */
    case 0102: case 0103: case 0120: case 0123: case 0124: case 0131:
        ...
    default:
        u = reg[016] >> 9;           /* 011225 >> 9 = 0o11 */
        if ((u >= 030) && (u < 070)) { ...set volume offset... }
        return E_UNIMP;
    }
}
```

Диспак假设 reg16 содержит **номер системной функции**. Значение `011225(8)`
ни под один `case` не подходит, а `u = 0o11` вне диапазона `[030, 070)` →
возвращается `E_UNIMP` — «функция не реализована».

### 4.3 Дальнейший путь ошибки

`dispак/cu.c:915` (`errchk`):

```c
if (err == E_UNIMP) {
    spec_saved = spec;
    reg[PSSREG] = ...;
    supmode = 0100000;
    JMP(XCODE_ENTRYPT);      /* = 011, defs.h:202 */
}
```

Управление передаётся на точку входа супервизора 011, который не умеет
обслужить каталожную заглушку как запрос, и задача завершается аварийно.

### 4.4 Формат операнда Э62 по книге Тюрина (уточнение диагноза)

Книга Тюрина (1985) «ОС ДИСПАК», страницы 332–333 по тексту (PDF 333–334),
раздел «ИР Э62 А, где АИСП», перечисляет субкоды Э62 — малые восьмеричные
числа `0000`, `0040`, `0043`–`0047`, `0050`–`0057`, `0060`–`0067`,
`0070`–`0076`, `0101`–`0105`, `0117`, `0123`, `0125`, `0126`, `0130`.
Там же, в конце перечня, стоит строка:

> АИСП ≥ 30 000 — задание сдвига по магнитному носителю или отказ от
> носителя информации (страница 278).

Подробности на страницах 278–279: «1—9 разряды АИСП — величина сдвига начала
отсчёта зон (Δ), 000…776(8), 777(8) = освободить МЛ/МД; 10—15 разряды —
виртуальный номер устройства НУ, 30(8) ≤ НУ ≤ 67(8)».

Проверка в `dispак/extra.c` (`u = reg[016] >> 9; 030 ≤ u < 070;
offset = reg[016] & 0777`) **дословно совпадает с книгой**. Для `011225(8)`:
сдвиг = 225(8), НУ = 011(8) — вне допустимого диапазона 30…67(8), а само
число меньше 30 000(8). Следовательно `E_UNIMP` — **корректная**, а не
ошибочная реакцияДиспак. Ранее это место ошибочно считалось «недостатком
обработчика».

Реконструкция «блок-запроса» из `p18.16-2` (`ИА ≥ 010000` → код из первого
слова `[reg16]`, протокол ekdisp «уии м16(м4)», утраченный патч `148ed81`)
книгой не подтверждается. В родном супервизоре `ekdisp.b6:66-70` действительно
читается `уии м16(м4)` — код функции из ячейки по исполнительному адресу —
но это относится к другой редакции системы (ОС-93, таблица в `rukava.be`).
Для каталожной заглушки этот протокол не применяется: дамп ядра в момент
трапа показывает, что `[011225]` содержит `0o0037002202611252` — фрагмент
Fortran-runtime, а не код запроса.

**Вывод:** спорить о формате операнда Э62 бессмысленно — «команда»
`Э62 74400(М10)` не является настоящим вызовом Э62. Это слово записи
каталога PERSO (дата/длина), случайно дизассемблированное как команда. По
архитектуре оно не должно исполняться вообще: при линковке внешнего символа
загрузчик обязан подменить его на переход к телу модуля.

## 5. Источник проблемы (итоговый диагноз)

**Источник проблемы — отсутствие вДиспак линковки внешних символов
PERSO-библиотеки, а не обработка Э62.**

При сборке `GLNUM.FTN` загрузчик ФОРЭКС оставляет в памяти задачи каталожные
заглушки: для каждого внешнего имени (`ATM`, `NR`) слово записи каталога
должно быть заменено на переход к телу модуля (механизм PERSO, символы входа
`C = 0o6700`).Диспак такой подмены не выполняет — поиск по исходникам не
обнаружил обработки `0o6700` ни в одном модуле. В результате слово каталога
остаётся в памяти, при исполнении дизассемблируется как `Э62 74400(М10)` и
уводит задачу в `e62()` с бессмысленным операндом.

Диспак здесь **не ошибается**: его `e62()` реализует книжный формат Тюрина,
и `E_UNIMP` на `011225(8)` — правильная реакция (раздел 4.4). Ошибка лежит
раньше — на этапе линковки, а не в обработчике экстракода.

Подтверждения:

1. Библиотека физически корректна: каталог зоны 3000(8) тома 2348 читается
   обратно побайтово, содержит ATM/NR, соседние зоны не затронуты.
2. Карты подключения корректны: при `*LIBRARY:43/44` (`i > 24`,
   математический номер объявленного тома) надписи «ОТСУТСТВУЕТ NR/АТМ»
   исчезают — имена находятся.
3. Гипотеза «перенаправить LIBRARY:1 на зону 3000» проверена и опровергнута
   как решение: соответствие «номер библиотеки → зона» хранится в системной
   таблице LTAPES (ячейка 73B, список в ОЗУ по адресам 0104000…0110000), а
   не в одной ссылке объектного модуля. Патч строки `1500-1701` →
   `3000-3039` в каталоге зоны 0 тома 2048 и замена содержимого зон
   1500–1701 каталогом с ATM/NR не снимают «ОТСУТСТВУЕТ NR/АТМ» —Диспак
   не использует этот каталог для LIBRARY:1.
4. Падение происходит строго в `e62()` на `reg16 = 011225`, а не при поиске
   имени, не при чтении каталога и не при обращении к диску.
5. Готового патча линковки нет: коммит `148ed81` утрачен, во всех ветках и
   бандахДиспак обработчика `C=0o6700` не существует.
6. Сам хост-кодДиспак не разбирает карты `*LIBRARY` — это делает код
   Монитора-80 в эмулируемой памяти (`loadlibr.asm`). Список LTAPES лежит в
   ячейке 73(8) (`core[0o73]`), а запись каталога на системном томе не содержит
   поля номера тома. Поэтому перенаправить LIBRARY:1 на зону 3000 **другого**
   тома нельзя даже правкой каталога: максимум — зона 3000 того же тома 2048.
   Подмена ячейки 73(8) через отладчик (`dispak -b`, `73 = <слово>`) действует
   только на один прогон и LTAPES пересоздаётся заново при каждом старте.

## 6. Почему не помогают обходные пути

| Попытка | Результат | Причина |
|---|---|---|
| `*personal library:413000` | Имена находятся, падение в Э62 | Заглушка каталога — не системная функция |
| `*LIBRARY:30` | `ddio: E_CWERR u=30 zone=0000` | Логическое устройство 30 не смонтировано |
| `*LIBRARY:43/44` | Имена находятся, падение в Э70 (03064) | Та же проблема канала 46/54 в рантайме |
| `*call librefer` + 2248 | «ЗАТЕРТО СПО», «ОШ.В ИНФ.СЛ.ЭКСТ» | Библиотекарь — отдельная задача монитора, конфликтует с колодой |
| `*super/*perso:401350` | Конфликт по области СПО | Загрузка библиотекаря в область стандартной программы отладки |
| Строка `1500-1701` → `3000-3039` в каталоге зоны 0 тома 2048 | Запись `*LIBRARY:1` меняется, но «ОТСУТСТВУЕТ NR/АТМ» остаётся |Диспак не использует этот каталог для LIBRARY:1; запись не содержит номера тома |
| Замена содержимого зон 1500–1701 тома 2048 каталогом с ATM/NR (332 записи) | Имена по-прежнему «ОТСУТСТВУЕТ» | Не снимает главный блокер — отсутствие линковки внешних символов |

Общий итог таблицы: все перечисленные пути лишь меняют **способ поиска имени**.
Ни один из них не подменяет каталожное слово на переход к телу модуля, поэтому
ни один не устраняет падение.

## 7. Итоговое решение и рабочее состояние

Направление LIBRARY/PERSO **закрыто как тупиковое** в текущей конфигурации
Диспак. Библиотека на томе 2348 (зона 3000) остаётся в образе как артефакт,
но не как доказательство работоспособности вызовов ATM/NR.

Поддерживаемая конфигурация игры — `SRC/GLNUMR.FTN`: атмосфера и случайные
числа реализованы непосредственно в задаче, без вызовов внешней библиотеки.
Контрольный прогон на томе 2348 проходит чисто (завершение кодом 411, ошибок
201 нет); артефакты — `RUNS/run-2026-11-17-clean/`.

Для полноценной работы с библиотекой потребовалась бы реализация вДиспак
**линковки внешних символов PERSO**:

1. поиск записи в каталоге по имени внешнего символа (`ATM`, `NR`);
2. чтение тела модуля (`cmd/const`) и перераспределение адресов;
3. подмена каталожного слова на переход к телу модуля, включая символы входа
   `C = 0o6700`, и запись точки входа.

Пункт «блок-запрос Э62 (`reg[016] ≥ 010000` → код из `[reg16]`)» из прежней
формулировки снят: он относился к утраченному патчу `148ed81` и книгой
Тюрина не подтверждается (раздел 4.4). Это отдельная крупная задача реверса,
которую не следует смешивать с настройкой LIBRARY.
