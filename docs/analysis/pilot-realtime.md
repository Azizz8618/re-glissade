# Доставка команд пилота в реальном времени (этап Q6)

Дата: 19 ноября 2026 года. Отчёт по модулю `TOOLS/pilot_queue.py` —
очереди команд пульта пилота и инструктора для тренажёра «Глиссада-6».

---

## 1. Что сделано

Модуль `TOOLS/pilot_queue.py` читает заранее подготовленную очередь событий,
следит за границами шагов модели и в нужный момент пересылает код команды
в ячейку системного запроса Э-60 (`0154`) через готовый мост ДКС
из `TOOLS/sm2_dks_bridge.py`. Мост загружается по пути файла, так же,
как это делает `TOOLS/timeline.py`; сам мост не изменялся.

Состав модуля:

| Часть | Назначение |
|---|---|
| `COMMAND_CODES` | явная таблица кодов всех команд пульта |
| `encode_command`, `decode_command` | преобразование «команда — код» и обратно |
| `Event`, `parse_event` | проверка одного события при чтении |
| `PilotEventQueue.from_file` | загрузка файла событий |
| `due(step)` | выбор команд, срок которых наступил |
| `deliver(link, step)` | передача команд через соединение моста и журнал «ОТПРАВЛЕНО» |
| командная строка | пробный прогон без сети и живой режим |

Как и во всём плане `PLAN-PERIFERIYA.md`, хост только перевозит данные
и задаёт темп. Модели подсистем и приём команд должны исполняться на СМ-2.

## 2. Как задавать события

Файл событий — текстовый, одна строка — один объект с полями `step` и `cmd`:

```text
{"step": 1, "cmd": "STA"}
{"step": 2, "cmd": "EV+"}
{"step": 3, "cmd": "EV+"}
{"step": 4, "cmd": "AI-"}
```

Правила:

- `step` — целое номер границы шага модели, начиная с единицы;
- `cmd` — имя команды из таблицы ниже; регистр и краевые пробелы не важны;
- пустые строки пропускаются;
- события сортируются по шагу, внутри одного шага сохраняется порядок записи;
- неизвестная команда, дробный или нулевой шаг, повреждённая строка — ошибка
  на этапе загрузки, а не во время прогона.

Семантика `due(step)` накопительная: выдаются все ещё не доставленные
события, у которых номер шага не больше текущего. Если цикл пропустил
границу, команда не теряется и уйдёт при первом же вызове с большим номером.
Повторно одна и та же команда не выдаётся; для повторного прогона есть
метод `reset()`.

## 3. Таблица кодов команд

Код записывается в младший байт 16-разрядного слова, старший байт равен нулю.
Диапазоны 9–15 и 24–31 оставлены свободными. Назначение ручек управления
взято по `SRC/GLDIAL.PAS`: `EV` меняет руль высоты, `AI` — элероны,
`RU` — руль направления, `TH` — тягу.

| Код (дес.) | Код (восьм.) | Команда | Назначение |
|---:|---:|---|---|
| 1 | 0001 | `EV+` | руль высоты: прибавить отклонение |
| 2 | 0002 | `EV-` | руль высоты: убавить отклонение |
| 3 | 0003 | `AI+` | элероны: прибавить отклонение |
| 4 | 0004 | `AI-` | элероны: убавить отклонение |
| 5 | 0005 | `RU+` | руль направления: прибавить отклонение |
| 6 | 0006 | `RU-` | руль направления: убавить отклонение |
| 7 | 0007 | `TH+` | тяга: прибавить |
| 8 | 0010 | `TH-` | тяга: убавить |
| 16 | 0020 | `STA` | запуск моделирования |
| 17 | 0021 | `STE` | один шаг моделирования |
| 18 | 0022 | `STO` | останов моделирования |
| 19 | 0023 | `PAR` | параметры и перезапуск |
| 20 | 0024 | `PRN` | печать формы |
| 21 | 0025 | `AUTO` | включение автопилота |
| 22 | 0026 | `INS` | переход в режим инструктора |
| 23 | 0027 | `EXIT` | выход из тренажёра |
| 32 | 0040 | `SEL` | выбор упражнения |
| 33 | 0041 | `FRZ` | заморозка модели |
| 34 | 0042 | `UNF` | снятие заморозки |
| 35 | 0043 | `INJ` | ввод отказа |
| 36 | 0044 | `EPS` | задание порога ошибки |
| 37 | 0045 | `REC` | включение записи |
| 38 | 0046 | `RPL` | воспроизведение записи |
| 39 | 0047 | `RST` | очистка записи |
| 40 | 0050 | `SCR` | вывод снимка |
| 41 | 0051 | `HLP` | справка |
| 42 | 0052 | `PIL` | возврат в режим пилота |

Команда `PFL` встречается в исходнике `GLDIAL.PAS`, но в таблицу не включена:
её нет в заданном перечне команд пульта. Это расхождение зафиксировано,
а не «додумано» молча.

## 4. Как запускать

Пробный прогон — без сети, показывает план доставки:

```sh
cd /home/azizz/Yandex.Disk/re-glissade
python3 TOOLS/pilot_queue.py --events /tmp/pilot-events.jsonl --dry-run
```

Фактический вывод для файла из раздела 2:

```text
ПРОБНЫЙ ПРОГОН: событий 4
ДОСТАВКА: шаг=1 команда=STA код=000020 адрес=000154
ДОСТАВКА: шаг=2 команда=EV+ код=000001 адрес=000154
ДОСТАВКА: шаг=3 команда=EV+ код=000001 адрес=000154
ДОСТАВКА: шаг=4 команда=AI- код=000004 адрес=000154
ПРОБНЫЙ ПРОГОН: сеть не использовалась
```

Живой режим подключается к серверу моста ДКС:

```sh
python3 TOOLS/pilot_queue.py --events /tmp/pilot-events.jsonl \
    --host 127.0.0.1 --port 4140
```

Дополнительные ключи:

- `--addr 154` — другая ячейка Э-60, число восьмеричное; по умолчанию
  берётся `CELL_REQUEST` моста, то есть `0154`;
- `--tick 0.1` — пауза между шагами в живом режиме, секунды;
- `--log <файл>` — записать сообщения о доставке в файл;
- `--table` — напечатать таблицу кодов и выйти.

Помимо сообщений модуля, соединение `DksLink` само печатает строки
«ОТПРАВЛЕНО» и «ПОЛУЧЕНО» с байтами кадра. Каждая команда уходит отдельным
кадром `WRITE` с квитированием `D7`.

## 5. Как связать с тактированием

Файл `TOOLS/timeline.py` в этой задаче не трогался. Точка подключения — цикл
по шагам после выдержки масштаба времени; соединение с мостом уже создано
в этом цикле, второе соединение открывать нельзя:

```python
import pilot_queue

queue = pilot_queue.PilotEventQueue.from_file(
    args.events, log=frame_log.append)

for k in range(args.ticks):
    step = k + 1
    # ... выдержка до целевого модельного времени ...
    queue.deliver(link, step)
    # ... кадр PING и запись строки журнала ...
```

Если событий на шаге нет, `deliver` возвращает пустой список и в сеть
ничего не уходит. Для одного шага с несколькими командами записи идут
последовательно в порядке из файла. Порядок вызова относительно `ping()`
не критичен для транспорта, но для журнала удобно сначала доставить команду,
а затем отметить кадр тактирования.

## 6. Тесты

```sh
python3 -m unittest TOOLS.tests.test_pilot_queue -v
```

Результат: 21 тест, все пройдены. Проверены загрузка файла событий,
сортировка по шагам, границы `due()`, накопительная семантика и отсутствие
повторной доставки, таблица кодов и её обратное преобразование, отправка
через подставной объект с методом `write`, а также пробный прогон
и обработка ошибок в командной строке.

## 7. Честный разрыв

1. **Обработка команд внутри прошивки не восстановлена.** Хост кладёт число
   в ячейку `0154` и получает квитирование кадра. Настоящий разбор этого
   слова внутри `СВЯЗЬ7` и `GLDIAL.PAS`, действие на рули и переключение
   режимов не реализованы. Таблица кодов — наша декларация, а не коды
   подлинного пульта.
2. **Прямой связи регистра `SM2KD` с сокетом нет.** Как и в отчёте
   `sm2-dks-bridge.md`, хост работает с кадрами ДКС и генерацией команд
   для контроллера 2К; правка `hp2100_sm2k.c` не входила в задачу.
3. **Квитирование подтверждает только транспорт.** Ответ `D7` на `WRITE`
   говорит, что кадр принят мостом, но не то, что задача на СМ-2 прочитала
   команду. Чтение ячейки ответа `0157` и асинхронный `ATTN` не обрабатываются.
4. **Живой режим против настоящего сервера проверен 19 ноября 2026 года**
   (см. раздел 9); GAP остаётся в обработке команд внутри прошивки.
5. **Очередь не знает о приоритетах прерываний.** В плане `PLAN-PERIFERIYA.md`
   команда пилота должна становиться событием с кодом источника и приоритетом
   по номеру; здесь реализована только упорядоченная доставка по шагам.

## 9. Проверка интеграции с живым мостом (19 ноября 2026 года)

Поднят `pdp11` с конфигом `BESM6/OSZAGR/e60_R0.ini` (`SET DKS BRIDGE=4140`)
в каталоге `/tmp/.private/azizz/opencode/ps2int`. Очередь из трёх событий:

```json
{"step": 1, "cmd": "EV+"}
{"step": 3, "cmd": "AI-"}
{"step": 5, "cmd": "STA"}
```

Прогон `python3 TOOLS/timeline.py --ticks 5 --scale 20 --event --events /tmp/events.jsonl`:

```
шаг=1 ... событие=D7 PING ... EV+=000001
шаг=3 ... событие=D7 PING ... AI-=000004
шаг=5 ... событие=D7 PING ... STA=000020
```

Задержка доставки на каждом шаге — около 0,0003 с при модельном шаге 0,1 с,
то есть **значительно меньше одного шага** (требование Q5 выполнено).
Контрольный `READ` ячейки `0154` через `sm2_dks_bridge.py` вернул `000020`
(код команды `STA`) — код действительно оседал в ОЗУ Э-60.

Командная строка самого `pilot_queue.py` (`--dry-run`) и 21 модульный тест
проходят. Хост по-прежнему только транспортирует код команды; разбор слова
внутри `СВЯЗЬ7`/`GLDIAL` не восстановлен.
