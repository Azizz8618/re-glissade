# п.18.19 — Реверс классификатора листа 10633 и контракт листа при дозагрузке
(А2, сессия 14.11-26)

Цель п.18.18(е)(1): «реверс классификатора 10633/структуры листа
(регионы 01000-01240, 10577-10640; сравнить со свежим стартом k46, где
[11201]@0o12 проходил, и п.9.6, где [11201]@0o12 давал статус 0o21)».

## 1. Метод

Прогон GLIS1R-NL.B6 в натуральном пути (`TOOLS/run_glis1r.py`,
`GLIS1R_NATIVE=1 GLIS1R_SEED=none`), смерть
`ИСПОРЧЕН РЕКОРД LUN 5 RET 01744 DEV 00045 CZ 00000 POINT 00012`.
Инструменты за прогон: `BESM6_CORE_ON_PC=01110` (дамп ядра в момент
печати ИСПОРЧЕН; pc=76431 — класс-проверка), `BESM6_CORE_ON_PC=76431`
(ранний hit — только для дизассма), `BESM6_WATCH` (37012, 76044, 12,
75441, 75443, 11176), MTR-окно 10577-10645 (death-проход), лог Э70
(`SHEET`, добавлен в dispak/extra.c: слово 0o12 буфера 37000 при каждом
обмене зоны 20/04).

Ключевое отличие дизассма: `core-pc.bin` не содержит overlay-членов
(страничный своп), а `core-uic.bin` (кэш команд по виртуальным pc)
содержит всё, что исполнялось — дизассм классификатора выполнен из
кэша (TOOLS/disasm_uic.py).

## 2. Классификатор 10633 (IОХХFМR*) — дизассм

```
10633  wtc 0043(0) | xta 76000(4)     ; acc := [76000 + М4]   (МТР: 10633R xta 76000(4))
10634  aex 0006(2)  | vtm 0003(16)    ; acc ^= [М2+6]  (эталон-6); М16 := 3
10635  uza 0640(0)  | aex 0006(2)     ; ==0 -> 10640; иначе восстановить acc
10636  aex 0007(2)  | vtm 0000(16)    ; acc ^= [М2+7]  (эталон-7); М16 := 0
10637  uza 0640(0)  | vtm 0001(16)    ; ==0 -> 10640; иначе М16 := 1 (тип 1)
10640  ita 0016(0)  | atx 0003(1)     ; [М1+3] := тип  ([75443] при М1=75440)
10641  uj  0000(6)                     ; возврат по М6
```

- Эталоны — **динамические слова** `[М2+6]`/`[М2+7]`. В death-вызове
  М2=11172: `[11176]=0o2400000000000000`, `[11177]=0o1000000000000000`.
- Тип 1 не совпал → статус: `10724L atx 3(1)` с AU=0o21 ([75443] := 0o21),
  затем печать ИСПОРЧЕН (`01110`, Э70 u=07 z=34, М16=75456).
- Death-контекст: М1=75440, М2=11172, М4=0o12 (POINT-позиция),
  [75444]=0o45, [75445]=0o34, [75446]=0o12 (в печать POINT 00012).
- [75441]=1 в дампе НЕ перезаписывается смертью (WATCH: 41 записей —
  все лексикон, нули); «тип» живёт в [75443].

## 3. Хронология death-классификации (MTR 10577-10645)

```
11065L vzm 11123(3)  AU=6400000000000000      ; caller, acc=[11201]-подобная проверка
11065R vjm 10702(15)  -> 10702L vjm 10633(6)
10633R xta 76000(4)  -> acc = 0o4024160122640520   (!!! не [11201])
10634L aex 6(2)      -> 0o7024160122640520 ≠ 0
10636L aex 7(2)      -> 0o2024160122640520 ≠ 0
10640R atx 3(1)      -> [75443] := 1
10724L atx 3(1)      -> [75443] := 0o21
```

В native13 (развёртка v1) классификация шла ДО доставки конверта в
буфер: [76012] = старьё 0o4024160122640520. В native17 (fetch прямо в
76000) [76012]=[11201], [76013]=ключ уже при смерти — но эталоны
death-вызова (0o24<<42 / 0o10<<42) не совпадают и с маркером:

```
0o6000000000000000 ([11201]) ^ 0o2400000000000000 = 0o4400000000000000 ≠ 0
0o6000000000000000 ^ 0o1000000000000000 = 0o7000000000000000 ≠ 0  -> тип 1
```

Эталоны — динамические: РЛС-ротация Э75 ходит через [11176]
(`76424R *75 0(5)`), лексикон-эра пишет туда 0o5112-слова
(`06210R atx 10003(16)`). K46-дамп (TSTREAD) показывает в 11176/11177
совсем другой overlay-контент (0o4412-слова лексикона) — форматный
конвейер ФОРТРАН-READ(5) (IOXXFMR-путь, п.14.8) формирует эталоны из
FORMAT-структуры и ждёт на позициях конверта СВОИ слова, а не маркеры
k12. В 14.8-эре h-сид проходил IOXXFMR до POINT 00044 — сверить
эталоны тех прогонов.

Конволюционная гипотеза снята: дамп convol[37000..]/[76000..] в момент
смерти = нули везде (CV-лог), в ядре конволюция не хранится.

## 4. Контракт k12-конверта (подтверждён эталоном seed-k12.bin)

| позиция | слово | conv |
|---|---|---|
| 0o00 | 0o22015 (счётчик) | 1 (CONV_CMD) |
| 0o01-0o11 | лесенка 0o64<<42 … 0o24<<42 | 1 |
| 0o12 | [11201] (лист продолжается) | 1 |
| 0o13 | ключ-вес головы 0o34<<42 («ключ@граница+1», п.18.9в) | 2 |
| границы 0o12+0o32k (0o44, 0o76, …) | [11201]; последняя = [11200] (конец) | 2 |
| запись [b+1..b_next-1] (0o31 слово) | 12 слов ISO-72 + EOR 0o1002004010020012 + филлер 0o1002004010020040 | 2 |

## 5. Развёртка v1 (п.18.18) — дефект, доказанный дампами

- Конверт v1 = 13-словные записи (12 ISO + EOR) без маркеров на
  границах 0o44/0o76 и без ключей → первая же класс-проверка получает
  не-маркер → тип 1 → 0o21 → ИСПОРЧЕН POINT 00012.
- Все М16=45 fetchи до УИК-проверки (nat_armed) = приёмный спул МОНЫ:
  148 SHEET-событий RD/WR зоны 20/04 (RD pc=00052/00726/01777, WR
  pc=00452/01775); развёртка срабатывает на death-fetch (последний RD).
- Буфер 37000 затирается печатью/лист-обменом; [0600] после arming
  указывает на 0o37012/0o77146 (старьё), в k46 МОНА ставит его в
  конверт сама (0o76153 после прохода через [11200]@0o130).
- В k46 walker шёл маркерами: М4=М5 = 0o44 → 0o76 → 0o130; [75443]=0o33
  (И16:=3 «конец листа»), [75444]=0o130. В native-смерти walker стоял на
  0o45 (= граница 0o44 + 1 — позиция ключа).

## 6. Развёртка v2/v3 (реализована в dispak, env-gated)

`BESM6_LUN45_NATIVE=1` + `BESM6_NTV_TRACT` (умолч. 06):
1. конверт k12-формата (таблица выше) строится из нативной зоны УИР
   20/04 (декод RLE-записей, карты после *EXECUTE включая *END FILE) и
   пишется на ОТДЕЛЬНЫЙ тракт 06 — native-зона МОНЫ не трогается
   (дек RLE нужен трансляции через word-pointer [0600], перекачка дек-а
   в буфер 76000 завершается до УИК-проверки);
2. fetch'и задачи (М16=45, чтение целой зоны, после nat_armed)
   redirect'ятся на тракт 06 прямо в лексем-буфер 76000
   (`uil.i_addr=07600`: классификатор читает [76000+М4] немедленно,
   МОНА-копия из 37000 не успевает — native16);
3. KCOUNT[0600] := 0o76012 — один реарм (native7 ломал разбор записью
   на каждом входе конвейера с мусорной позицией 0o77144);
4. пустой лист [11200]@0o12 на ЛУН46 (05) — конец очереди GIVELEXX.

Проверки: конверт v3 в dd-дампе (тракт 06: 0o22015 + лесенка +
[11201]@0o12 + ключ@0o13 + карты) и в буфере 76000 при смерти.
Смерть сохранилась — блокер перенесён в эталоны форматного конвейера
(раздел 3). Регресс-тест k46 (TSTREAD + seed-k12) — штатный КОНЕЦ
ЗАДАЧИ, ИСПОРЧЕН 0.
