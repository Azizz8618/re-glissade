# Память проекта «Глиссада-6 / тренажёр»

## Известные ошибки и решения

- **Расчёты модели — в Фортране ядра, а не в хостовом Python** (коррекция
  пользователя 2026-11-19). Рельеф, просвет, столкновение с землёй и
  подобные вещи должны считаться внутри игры (`SRC/*.FTN`) и Printing
  в кадр АЦПУ. Хостовой слой допустим только как транспорт, тактирование
  и просмотрщик, но не как источник истины для физики.

- **Диагностика и пользовательское окружение — только на русском**
  (коррекция пользователя 2026-11-18). Все сообщения инструментов,
  подсказки и отчёты писать по-русски, без английских слов и смешанных
  конструкций. Машинные токены (`OCENKA=`, `VERT=`, `DALN=`, `TELE`, md5),
  которые разбирают скрипты, сохранять как есть. Подробности —
  `docs/corrections.md`.

- **Параметры сразу выносить в отдельные блоки переменных** (коррекция
  пользователя 2026-11-18). Корректируемые числа не размазывать по телу
  подпрограмм: держать их в именованном `COMMON`-блоке (Fortran) или
  блоке констант (Pascal). Физическая ёмкость массива — одна константа,
  логический лимит — поле параметного блока. Причина: разбросанные
  литералы нельзя править в одном месте, а разросшийся буфер вытеснил
  `GLDIAL` из PERSO-зоны 2700. Подробности — `docs/corrections.md`.

- **PERSO-зона 2700 ограничена 8 зонами × 1024 слова.** После добавления
  крупного COMMON-массива обязательно проверять каталог: если `GLDIAL`
  пропал, `*call gldial` даёт `ОТСУТСТВУЕТ GLDIАL`, а `scenarios.py verify`
  показывает `None` вместо метрик.

## Полезные факты

- Ведущая программа — Pascal `GLDIAL` (PERSO 2700), ядро — Fortran через
  `FORTRAN;`. Регрессионный барьер — 10 исторических сценариев.
- Диск: `~/.besm6/2348`. Сборка: `TOOLS/build-dialog.py`, установка:
  `sh TOOLS/install-2348.sh 1`.
- Имена Fortran-модулей и COMMON-переменных ≤ 6 литер (ФОРЭКС).
- Подробности — `docs/corrections.md`, `docs/PLAN-TRENAZHER-K71.md`.

## Периферия и эмуляторы (19 ноября 2026 года)

- Задачи ПВС исполняются на эмулируемой СМ-2 (`SET CPU SM2` в `hp2100`),
  хост только переносит данные и задаёт темп. Кодировка команд объявлена
  в `../simh/HP2100/sm2_params.h` и не сверена с подлинным железом.
- `SET SM2K SC=2` неприемлемо: коды `0…017` служебные, рабочий диапазон
  начинается с `020`. Разные величины: канал КРК Э-60 (`--chan`) и
  код выборки СМ-2 (`--sm2-sc`) — разные величины.
- Загрузка соседнего модуля через `importlib` требует регистрации в
  `sys.modules` до `exec_module()`, иначе `dataclass` падает с
  `AttributeError: 'NoneType' object has no attribute '__dict__'`.
- `DksLink` не подключается в конструкторе — нужно явно вызвать
  `connect()`; `ping()` возвращает `DksFrame`, а не байты.
- SIMH читает консоль только при `isatty(0)`: для интерактивного ввода
  нужен `pty.fork()`, обычный pipe не работает.
- Рабочий каталог `../simh/master` содержит чужие незакоммиченные
  изменения — не трогать. Патч C-кода делать только в отдельном чистом
  worktree; решение по `hp2100_sm2k.c` — оставить GAP.
