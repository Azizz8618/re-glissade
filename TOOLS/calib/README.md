# КАЛИБРОВОЧНЫЕ ПРОГРАММЫ

Инструменты для проверки и настройки автопилота `GLAUTO` при изменении
ТТХ (см. `docs/analysis/ttx-audit.md`). Все программы перенесены сюда
после проверки 18 ноября 2026 года.

## Состав

| Файл | Назначение |
|---|---|
| `CALIB.PAS` | драйвер: за один прогон считает все 5 типов и печатает метрики `999 <тип> <VERT> <TCH> <H> <N> <OCENKA>` |
| `CALIB-SIG.PAS` | то же при `SIGW=0` (штиль) — отдельная проверка модели без турбулентности |
| `CALIBD.PAS` | отладочная версия с печатью траектории МиГ-15 каждые 100 шагов |
| `run_calib.py` | сборка колод и прогон; извлекает метрики из лога |
| `run_calib_sig.py`, `run_calib_d.py` | варианты для CALIB-SIG и CALIBD |
| `tune.py` | прогон заданного списка наборов коэффициентов (JSON) |
| `search.py` | случайный поиск коэффициентов по всем пяти типам |
| `search_level.py` | поиск по одному уровню `CALIB_SIG` |
| `write_glgain.py` | генерация `SRC/GLGAIN.FTN` из `best.json` и `levels/` |
| `verify_all.py` | проверка всех типов в самой игре: `verify_all.py <SIGW>` |
| `scenarios.py` | исторические сценарии: `list/add/run/capture/verify/report` |

## Параметры GLAUTO

Коэффициенты задаются строкой из семи чисел для каждого типа:

```
[GE, GEW, OFF, HFL, VYF, KV, KD]
```

- `GE`  — усиление по отклонению от глиссады при штиле;
- `GEW` — то же при `SIGW>0`;
- `OFF` — смещение целевой глиссады, метры;
- `HFL` — начало выравнивания: `HCR+HFL`;
- `VYF` — целевая вертикальная скорость на выравнивании, м/с;
- `KV`  — усиление по ошибке вертикальной скорости;
- `KD`  — демпфирование по угловой скорости тангажа `X(10)`.

Порядок типов: 1 МиГ-15, 2 Ил-28, 3 Ту-104, 4 Ан-24, 5 Ан-2.

## Запуск

```bash
cd TOOLS/calib
python3 run_calib.py                 # базовый прогон
python3 run_calib_sig.py             # штиль
python3 run_calib_d.py               # траектория МиГ-15
python3 tune.py '[["метка",[[...],[...],[...],[...],[...]]]]'
python3 search.py 30                 # 30 итераций случайного поиска
```

Результат поиска — `best.json` с лучшими параметрами и метриками.

Диски: том 2348 копируется в `work/` (или `searchwork/`) из
`/usr/local/share/besm6`; остальные тома подключаются символическими ссылками.
Диспак запускается через `run_save_pty.py` из besm-crypto; на приглашение
`WHAT=` отвечаем переводом строки. Приложение `GLDIAL.PAS` использует
`PASTEL[3]:=[48]` — это убирает `WHAT=` при выводе программы; pty нужен
только для запросов при печати листинга.

## Исторические сценарии

Сценарии хранятся в `scenarios/*.json`: тип самолёта, `SIGW`, `RSEED`,
`DT0`, источник и ожидаемые метрики. Добавить и зафиксировать:

```bash
python3 scenarios.py add my-case --aircraft 3 --sigw 0.3 \
    --rseed 7351.5 --source "РЛЭ Ту-104"
python3 scenarios.py capture my-case
python3 scenarios.py verify
python3 scenarios.py report
```

`capture` записывает измеренные VERT/OCENKA/DALN как ожидаемые;
`verify` сверяет с допуском `tolerance` из JSON (по умолчанию 0.05 м/с
и 50 м). Прогон идёт в реальной игре из PERSO зоны 2700.

**Важно:** 18.11.2026 в `CALIB*.PAS` добавлена нормализация кватерниона
после РК-4 (как в `GLMAIN` и `GLDIAL`) — без неё калибратор расходился
с игрой. Драйвер печатает в лог, а не в АЦПУ-спул, поэтому метрики
доступны сразу, без декодирования `dd.m20`.
